# T-0613 [INS] Each institution has its own ledger account
REQ: REQ-INS-003, REQ-INS-006 (before T-0527) · Sprint: 11
Files: apps/api/src/ledger/accounts.ts, apps/api/src/institutions/collections.ts, apps/api/src/institutions/collections.test.ts, apps/api/src/institutions/allowance/activities.ts, apps/api/src/institutions/allowance/workflow.ts, apps/api/src/institutions/allowance/workflow.test.ts, apps/api/src/institutions/export.ts, apps/api/src/institutions/export.test.ts, specs/tasks/T-0613.md, specs/tasks/README.md
Test first: TST-INS-003, TST-INS-006. Every institution's money sat in one shared `institution_master` ledger account, told apart only by journal metadata, so no institution had a balance the ledger itself kept. Institution payouts (T-0527) need one: the decision (2026-10-20) is a per-institution account. `institution_master` is now owned by the institution's id, one per currency; fees credit it and allowances debit it, and `AccountService.institutionBalance` reads it. The export reads the institution's own account, and the shared one only for journals posted before this card. The tests cover: a fee lands in the paying member's institution's account and the other institution's stays at zero; an allowance run debits its institution's account and leaves the shared one untouched; a journal tagged with one institution that posted to another's account stays out of the first one's export.
Done when: listed tests pass; `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm trace` green; only listed files touched
Out of scope: institutions funding their account (deposits), and whether an allowance run may take the account below zero. Today it may, as it could before (the institution owes Kesher the difference). Payouts (T-0527) may not. Stop and ask on conflict with the spec.

As built:
- **No migration.** `ledger.account` already keys accounts by `(owner_party_id, type, currency)`, so the institution's account is the existing credit-normal `institution_master` type owned by the institution's id. `SYSTEM_OWNER`'s account keeps only the journals posted before this change; pre-launch, those come from tests and demo databases.
- **Export filter.** The export keeps its journal-tag filter and also requires the posting to be on the institution's own account, or the legacy shared one. A mistagged journal can no longer put another institution's money in an export.
