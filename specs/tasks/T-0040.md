# T-0040 [SETUP] Per-port provider binding: PROVIDER_<PORT> picks sim or an adapter, PROVIDER_MODE_DEFAULT may be sandbox
REQ: — (enabling; deploy readiness review 2026-11-05, docs/ops/deploy-readiness.md; after T-0659) · Sprint: 16 deploy
Files: apps/api/src/config.ts, apps/api/src/config.test.ts, apps/api/src/registry.ts, apps/api/src/registry.test.ts, apps/api/src/main.ts, apps/worker/src/main.ts, apps/api/src/infra-contract.test.ts, specs/tasks/T-0040.md, specs/tasks/README.md
Test first: today `apiConfigSchema` refuses every `PROVIDER_MODE_DEFAULT` except `sim`, and `envs/staging` passes `sandbox` while `envs/prod` passes `live`, so neither can boot (T-0025 left this on purpose until ADR-006). The only per-port override is `PROVIDER_INSTITUTION_BANKING` (T-0659). Generalise it: one `PROVIDER_<PORT>` key per port (`sim` by default, or a named adapter), each adapter's secrets required only when it is chosen, the choice logged once at start-up (port to adapter name, never a credential). `PROVIDER_MODE_DEFAULT=sandbox` is accepted when it only labels the binding mode; a port with no adapter chosen stays on its simulator. `infra-contract.test.ts` also checks the VALUES staging and prod pass against the schema (today it checks only that the keys exist), so a Terraform value the config refuses fails CI, not boot. Tests: a staging env block parses; a prod env block with a simulator for a port is still refused by T-0043's rule, not by this card; a half-set adapter env is refused naming the missing key.
Done when: listed tests pass; `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm trace` green; CI's terraform job green when `infra/` changed; only listed files touched
Out of scope: choosing which ports get which adapter (T-0041, T-0042); the production guard (T-0043); ADR-006 vendors (card processor, KYC, FX, payouts, sponsor bank), which have no adapter. Stop and ask on conflict with the spec.
As built:
- `PROVIDER_MODE_DEFAULT` is `sim` or `sandbox` in the API and worker config; it labels the environment only. `live` stays refused (T-0043 owns the production guard and flips prod's Terraform value).
- `PROVIDER_PORTS` in `apps/api/src/config.ts` is the one table of provider-choosing keys and each adapter's credential set; the Crowded checks now read it. A new vendor (T-0041, T-0042) is a row there, its keys, and a registry binding.
- A `PROVIDER_*` key the table does not own is refused, reported beside any other config problem, so a typo (or a key added before its card) cannot leave a port quietly on its simulator.
- `createRegistry` accepts `sandbox` as the same simulator registry under the staging label.
- `infra-contract.test.ts` loads the config with each root's `PROVIDER_MODE_DEFAULT`: preview and staging boot, prod is pinned as refused until T-0043.
- Not changed: the shared `ProviderSummary` type still lists only `institution-banking`; it grows with each vendor card.
