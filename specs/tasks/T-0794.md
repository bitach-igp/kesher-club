Behaviour: bind `stripe` only when `registry.bindingFor('billing', market)?.mode` is real (not `sim`) and `billing.stripe` is on; the verifier calls `port.parseWebhook`, maps `BillingError('BAD_SIGNATURE')` to `ok: false`, and returns the event id and a payload holding the parsed `BillingEvent` only (the raw body is not stored); the processor is a no-op that leaves the event unprocessed so T-0795 consumes it (and so `pending`/`lagMs` correctly show a backlog if the job stops). A processor error never loses the event (store first).
Test first (no TST id exists; new rows in `billing-events.test.ts`, with `FakeStripe`/the simulator billing port, no network): (1) a correctly signed `invoice.payment_failed` answers 200 and is stored once, unprocessed; (2) a forged signature and a timestamp older than 5 minutes answer 401 and nothing is stored; (3) the same event id twice answers `duplicate: true` and stores one row; (4) with the billing binding a simulator, or `billing.stripe` off, `POST /hooks/stripe` answers 404 and stores nothing; (5) an event type the port does not map is stored and left for the job to skip, never an exception.
