Source: /simplify review of 2026-11-19 (design note; every lead re-checked against origin/main at 123e75c). Verified: `AccountService.provisionMember` (`apps/api/src/ledger/accounts.ts:84-90`) runs `ensure` (select, insert, retry on unique violation) in a nested loop, `CURRENCIES` x `['wallet','pending']`, one at a time (4 round trips at least, more on a race); `purses` (`:143-154`) does two `ensure` and two `ledger.balance` reads per currency, serially; the module-level `ensureAccountRowReport` (`:24-35`) is the single-row upsert that the production bootstrap (T-0046) and the demo seed also call. Also `authorisation` system accounts (`:49-52`) loop the same way.
Design: one `insert into ledger.account (...) values (...), (...) on conflict (owner_party_id, type, currency) do nothing` for the whole set, then one `select ... where owner_party_id = $1 and (type, currency) in (...)`, returning the accounts in the SAME order as the loop did (currency order, wallet before pending); ids are still `uuidv7` generated by the app. `ensureAccountRowReport` keeps its `{ id, created }` contract (the bootstrap reports `created`). `purses` runs its balance reads with `Promise.all` per currency. The conflict target is the existing `unique (owner_party_id, type, currency)` (`db/migrations/ledger/0001_init.sql:16`); `normal_side` is a required column, so the batch must compute it per type exactly as `ensureAccountRowReport` does (read it first and reuse its helper); if that cannot be shared cleanly, keep the current retry-on-unique path and say so in the PR.
Test first: TST-WAL-001 (`ledger/accounts.test.ts`) unchanged and green. New: `provisionMember` twice returns the same four accounts in the same order with the same ids and creates no more rows; two concurrent calls for one party end with four rows and equal results; a partially provisioned party (only USD wallet) is completed without touching the existing row; `purses` returns the same `Purse[]` and balances as the pre-change fixture; the number of queries for a fresh member is recorded in the PR.
