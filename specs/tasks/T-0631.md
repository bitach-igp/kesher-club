## As built
- **No migration.** The deposit request takes an optional `caseId`. The case's credit fills the body, and the deposit
  id goes into the case's `payload` (`depositId`), with the case moving to `investigating`. `post()` then resolves
  every open suspense case naming that deposit and audits `case.resolved`. The update is keyed by status, so a
  repeat closes nothing. `app.ts` is untouched.
- **Nothing retyped, nothing guessed.** A field given with `caseId` must equal the case's own (422 otherwise); the
  bank reference is normalised exactly as the feed stores it, so the `(rail, bank_reference)` uniqueness makes a
  second recording 409 whether it comes from the case or is typed by hand.
- **The link follows the credit.** `ops.external_ref` (`institution_deposit`, provider, credit id) is written when the
  deposit is recorded; if an earlier recording of the same credit was rejected, the reference moves to the new one.
  A rejection also drops `depositId` from the case, so the queue does not point at a dead deposit.
- **Contract.** `amount`, `rail`, `bankReference` and `valueDate` are no longer schema-required (the server still
  requires them without `caseId`); loosening a request is not a breaking change for oasdiff.
