## As built
- **Screen** `/us-banking` (finance staff and admins; nav link `nav.usbank`): the application's state (not linked, pending, needs info, rejected with the support line, approved with last four and balance), then
  "Fund master account" once `canFund` (the bank approved AND `moneyOpen`, Kesher's KYB review): amount in dollars, a quote (fee, arrival date, expiry), a request with a passkey, and the list of requests with
  status, approve (a second finance user or admin; never offered on a person's own request) and cancel. Model in `src/us-banking.ts` (tested without a browser), copy in English and Hebrew, mirrored.
- **Flag.** The console has no flag read of its own, so "hidden unless the flag is on" is the API's 404 `FEATURE_OFF` on the status call: the page then sends the person home. The nav link shows for finance
  staff and admins regardless; following it with the flag off lands on the home page.
- **Application.** Admin only, as the API says. "Under Kesher's company" (a platform sub-account, no form) or "the institution's own US entity" (legal name and EIN, which opens the bank's hosted form in a new
  tab). The same application keeps its Idempotency-Key across a retry that did not land; a funding request keeps its key per quote.
- **Who may approve.** The screen reads the signed-in person from the access token's `sub` to hide their own request's approve button. That is a courtesy: the API refuses it (403) regardless.
- **Not done.** "Recent transactions" for an approved account: no API endpoint lists them (the status call returns last four and the balance), so the screen says they are not shown yet; the endpoint is a
  follow-up card. The institution's rejected application has no re-apply path here (the API fixes the decision).
- **Files outside the card's list:** `apps/console/app/us-banking/UsBanking.tsx` (the client half, like `Deposits.tsx`). No migration, so no desktop handoff.
