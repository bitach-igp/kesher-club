# T-0063 [SETUP] A JIT process: SERVICE_ROLE=jit serves only the card authorisation route and the status
REQ: — (enabling; found while starting T-0045, docs/ops/deploy-readiness.md finding 19; after T-0044) · Sprint: 16 deploy
Files: apps/api/src/main.ts, apps/api/src/config.ts, apps/api/src/config.test.ts, apps/api/src/server.ts, apps/api/src/server.test.ts, apps/api/src/infra-contract.test.ts, infra/terraform/envs/staging/main.tf, infra/terraform/envs/prod/main.tf (the jit health-check path only), specs/tasks/T-0063.md, specs/tasks/README.md
Test first: nothing in the repository reads `SERVICE_ROLE`. `envs/staging` and `envs/prod` pass `SERVICE_ROLE = "jit"` to a second ECS service per market, but it runs the same image and entry point as the api, so the "jit" host serves every route of the API with the api's database role and secrets. Make the variable mean something. `SERVICE_ROLE` is `api` (default for the api service) or `jit`; in `jit` the process mounts only `POST /jit/card-authorizations` and `GET /status` (everything else answers 404 before authentication), builds only the services the authorisation path needs, and does not start anything else. Tests: a `jit` process answers 404 for `/auth/otp` and 200 for `/status`; an `api` process still serves all routes; the config refuses an unknown role; the Terraform contract test passes `SERVICE_ROLE` only with a value the config accepts.
Done when: listed tests pass; `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm trace` green; only listed files touched
Out of scope: the database role the jit process connects as (T-0064 then T-0045); the JIT latency budget (T-0055). Stop and ask on conflict with the spec.
As built:
- `SERVICE_ROLE` (`api` default, `jit`) is an API config key. Terraform also passes `worker` to the worker service, whose config ignores it; the API config refuses `worker` and anything else.
- `createServer(app, { role })` and `dispatch(..., { role })`: in `jit` every route except `cardAuthorization` and `getStatus`, and MCP, answers 404 NOT_FOUND before authentication or any handler. `main` passes the config's role and logs it on `listening`.
- Not done, on purpose: the card also says the jit process "builds only the services the authorisation path needs". `createApp` still builds the whole graph; the route gate is what closes the surface, and the database role in T-0064 and T-0045 is what limits the damage. Slimming the composition is a larger change to `app.ts` and can be its own card.
- Found alongside: the jit module had no `health_check_path`, so its load balancer target group used the module default `/healthz`, which the API does not serve (the console does). Its targets would never have turned healthy. Both environments now health-check `/v1/status` (allowed on the jit role), and the contract test pins the path for the api and jit modules.
