## As built
- `GET /institutions/{id}/members/{memberId}` (`InstitutionStudent`) returns the roster row (`RosterList.one`, a
  `memberId` filter on the same query in `roster-list.ts`), the latest 20 allowance payments with their date,
  amount and status, and every fee item, due and paid.
- **Spend, two layers.**
  - The code reads the live `spend_detail` consent first. Without it the `spend` key is absent, not empty.
  - With it, the spend read runs inside a transaction that sets `app.institution_id` for that transaction, so
    org.member_spend's row-level security (T-0603) allows it when the API runs as `club_app`.
  - Before this card nothing in the API set that variable; the existing policy simply returned no rows.
  - The test runs the read under the real `club_app` role, with a real transaction as `src/pg.ts` opens one, both
    with and without consent.
- **Untrusted text.** Merchant names travel as data; the test's merchant reads like an instruction.
- **404s.** Another institution's staff, a member of another roster, and a malformed id all answer 404.
- **Outside the card's list:** `roster-list.ts` gains `one()`.
