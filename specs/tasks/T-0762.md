Architecture check (asked in the review note): `apps/api` already depends on `@kesher/adapters` (`apps/api/package.json:13`) and imports it in `registry.ts`, `webhooks/crowded.ts` and `institutions/crowded-keys.ts`, so importing `subAccountRef` from adapters would pass the dependency rules. It is still the wrong home: the `s:` grammar is the port's (the simulator makes the same refs), so it goes in `@kesher/ports`; `adapters/crowded/map.ts` re-exports it under the same names (adapter tests unchanged). `o:` and `p:` are our own markers, not vendor refs, so they stay in apps/api (`wallet/sub-account-markers.ts`).
Correction to the lead: the `funding_subaccount` row is always exactly `s:<chapter>` (`packages/adapters/src/crowded/member-sub-accounts.ts:168` returns `subAccountRef(chapterId)` for the sub-account and `subAccountRef(chapterId, deposit.id)` for the `funding_account` row), so the `s:<chapter>:<account>` branch of the webhook match is only ever exercised by the test's own seed (`crowded.test.ts:514`). The card replaces the match with equality on `subAccountRef(chapter)`, parameterised, no concatenation; the test seed for that shape is dropped.
