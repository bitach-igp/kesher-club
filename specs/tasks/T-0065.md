## As-built
- `POST /admin/legal/documents` (`proposeAdminLegalDocument`, 201, or 200 with the open request for the same draft) and `POST /admin/legal/documents/{requestId}/approve` (`approveAdminLegalDocument`, 200). No reject or list (kept minimal). Neither takes an idempotency key (like the plan admin routes), so `HEADER_OPS` is unchanged.
- The request is `ops.approval_request` kind `legal_publish`, scope `platform`, the whole draft plus `draftHash` in `payload`. Its subject is `legal_publish:{docKey}:{uuidv7}`, unique per proposal. Propose looks for an OPEN, unexpired request of that kind with the same `draftHash` (a hash of the whole draft, the date as an instant) under an advisory lock on the hash, and returns it (200); anything else, including a corrected draft or the same text after an earlier request was approved, refused or expired, is a new request (201). The request insert and the proposer's decision are one transaction. The proposer is the first of two approvers (as plan versions), so approving their own request is 409 `IDEMPOTENCY_CONFLICT`; a decided or expired request is also 409.
- Approval, `LegalService.publish` and the audit entry (`legal_document.publish`, reason = the English change summary, else a default) run in one transaction. Lock order: the approval row, then the document lock (`pg_advisory_xact_lock(hashtextextended('legal:'||doc_key, 0))`, taken in `LegalService.publish` and by the admin before its shadow check), then the audit chain. Numbering is therefore race-free per document; PGlite has one connection, so the test checks sequential numbering and that the lock is held until commit, not a true concurrent race (unverified on real Postgres).
- Effective date: RFC 3339 with Z or an offset (422 otherwise), not in the past (422). An approval after the date has passed is refused 409 and publishes nothing (the request stays open and lapses; propose again with a new date). A proposal (422) or approval (409) dated before a version of the same document already scheduled is refused, because `current()` picks the highest version already in force and the later-numbered one would shadow the scheduled one. The shadow check at propose time is not under the document lock; the one at approval is.
- Texts are plain text, never markup. Titles reject all control characters; bodies and summaries allow only line breaks and tabs; DEL and bidirectional overrides (U+202A-202E, U+2066-2069) are rejected everywhere (422). Limits count code points (title 200, body 200000, summary 2000) and are in the OpenAPI request schemas.
