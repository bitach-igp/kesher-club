## As built
- `/roster/import` (I05) reads a CSV in the browser: UTF-8 with or without a BOM, comma or semicolon. A file that
  is not UTF-8 (a Hebrew export in Windows-1255) is said so, not shown as garbage.
- The column mapping is guessed from English and Hebrew headers (`guessMapping`); each of the five API columns has a
  select the staff can change. Student name and parent email are required: without them, or with a column that is
  missing or shared by two headers, the call is refused before it is made.
- The API only reads commas, so the console sends the rows re-written comma-separated and BOM-free. The same data in
  a semicolon file or with a BOM is the same import.
- "Check the file" calls `importRoster` with `commit: false`. The report groups the API's errors by row, each with
  the column and the API's own message. "Import students" is enabled only after a clean check of exactly the file and
  mapping now on screen; changing either disables it again.
- A retry of the same input keeps its Idempotency-Key; a changed file, mapping or dry-run/commit choice takes a new
  one. The API replays by key whatever the body, so a commit never reuses the dry run's key.
- A commit whose outcome is unknown (it timed out, or failed with anything but a refusal: not `VALIDATION_FAILED`,
  `FORBIDDEN`, `NOT_FOUND` or `UNAUTHENTICATED`) keeps its key per input in `Attempt.unresolved`. A re-check in
  between does not replace it, picking the same file again does not drop it (`forgetFile`), and the next commit of the
  same input goes with it, so the server replays the first answer instead of importing the students twice. It is kept
  in memory only: storing it would put the file's student data in `sessionStorage`, so a page reload forgets it.
- That failure says the result is unknown and that choosing Import students again is safe (`import.error.commit`); it
  never says nothing was imported. The report's heading says once that data rows count from 1 without the column
  names; each rejected row is labelled just `Data row N`.
- A quote opens quoting only at the start of a cell, so `5" tall` is plain text (the API's reader differs, but the
  console re-writes every cell quoted as needed, so the API reads what staff see).
- Headers, cells and the API's messages render as React text children (`<bdi>`/`dir="auto"`), never as markup.
- Limit: 900,000 bytes of the JSON-encoded request (newlines and quotes count twice, so a file is safe up to about 800 KB; the copy says so), not the API's 2 MB. A server action's body is capped at 1 MB by default and `next.config.ts` is not
  on this card; raising both is a follow-up.
- No nav link yet: `layout.tsx` and the I04 roster page are not on this card, so I05 is reached at `/roster/import`
  until a follow-up links it from I04 and the dashboard's empty state.
