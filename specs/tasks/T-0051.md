# T-0051 [SETUP] A smoke suite that proves a deployed environment works
REQ: — (enabling; deploy readiness review 2026-11-05, docs/ops/deploy-readiness.md; after T-0040) · Sprint: 16 deploy
Files: tools/smoke/*.mjs, tools/smoke/*.test.mjs, package.json, docs/setup/deploy.md, specs/tasks/T-0051.md, specs/tasks/README.md
Test first: `tools/smoke` takes a base URL and checks, over HTTPS only: `GET /v1/status` is healthy and reports the deployed tag; the OpenAPI document served matches the committed one's operation count; TLS 1.3 only on the API host; the JIT host answers its health path; the admin host refuses a request from outside the VPN; the console `/healthz`; security headers on the web host; a webhook with a bad signature is refused with 4xx and does NOT claim an event id (T-0207); an unauthenticated money route answers 401. It never creates data. Exit non-zero on the first failure and print which check. Unit tests run it against a local `createApp`.
Done when: listed tests pass; `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm trace` green; CI's terraform job green when `infra/` changed; only listed files touched
Out of scope: authenticated end-to-end flows against sandbox vendors (T-0060). Stop and ask on conflict with the spec.

## As built
- `tools/smoke/index.mjs` (CLI: `--base-url` plus optional `--jit-url`, `--admin-url`, `--console-url`, `--web-url`, `--openapi-url`, `--expected-tag`, `--webhook-path`, `--strict`, `--allow-local`; each also an `SMOKE_*` variable), `checks.mjs` (the ten checks, run in order, first failure stops and exits 1, one PASS/SKIP/FAIL line each) and `lib.mjs` (the https-only URL guard and the single HTTP client: GET, HEAD and `postInvalid` only). `docs/setup/deploy.md` documents the command, variables and what each check means. The root `test` script gained `tools/smoke/*.test.mjs`.
- Tests (`tools/smoke/smoke.test.mjs`, 12): the checks run against a real `createApp` served over `node:http` (an API server and a `role: 'jit'` server; web, console and admin are small static servers); TLS uses injected fakes; a recording `fetch` proves no request is anything but GET, HEAD or the forged-signature POST, with no credential; `http://` (except localhost with `--allow-local`), credentials and a missing base URL are refused before any request.
- Deviations: (1) The API exposes no deployed tag and `apps/api` is outside this card, so `api-tag` compares `--expected-tag` with an `x-kesher-version` header or a `version`/`tag` status field, and SKIPs with a clear message when the API sends none (a failure under `--strict`). A follow-up card should make the API report its `IMAGE_TAG`. (2) The API serves no OpenAPI document, so `openapi-operations` needs `--openapi-url` and skips without it; the operation counter reads JSON or the committed YAML by a line scan (no YAML dependency). (3) The console has no `/healthz` route today (the admin app does), so `console-healthz` will fail against a console without one. (4) The forged-webhook check uses `POST /v1/webhooks/crowded`: a refused delivery leaves one forensic row (`ops.inbound_rejected`), the only side effect the suite can have. (5) Unverified: nothing was run against a real deployed environment (none exists), so the real TLS probe, the admin refusal and the header list are untested against AWS; the web header list is a judgement documented in `docs/setup/deploy.md`.
