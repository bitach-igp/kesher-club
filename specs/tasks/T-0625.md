Test first: TST-INS-012, TST-PO-001 (screen rows). After the 2026-10-20 decision (T-0623: "Own account only"), an institution's payout is a withdrawal to its own verified account, so neither the console nor the API takes a payee for it any more.
- `POST /institutions/{id}/payouts` takes `{ amount, reference }`. The API pays the active verified account, and a body that still names a payee is refused.
- `GET /institutions/{id}/payout-account` answers, to the institution's finance staff:
  - the masked account and its holder;
  - whether a change waits for Kesher compliance;
  - or that there is no verified account yet.
- I09's new-payout screen shows "To the institution's own account: … •••• 9999" and asks only for the amount and the reference. Without a verified account, or while a change waits, it says so and offers no form.
- The demo seed runs the yeshiva's automated KYB checks and records its own bank account, which a second compliance persona approves, so the demo can withdraw.

The tests cover:
- a body naming a payee answers 422;
- with no verified account, the GET says so and a withdrawal answers 422 `no_verified_account`;
- a withdrawal pays the active account, masked in the response;
- the console's draft has no payee fields and refuses more than the account holds;
- the seed's yeshiva has an active own account.

Done when: listed tests pass; Spectral clean; `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm trace` green; the withdrawal verified in Chromium against the T-0031 stack; only listed files touched
Out of scope: member payouts, which are unchanged; paying suppliers through Kesher, until the bank answers question 9. Stop and ask on conflict with the spec.

As built:
- `POST /institutions/{id}/payouts` takes `InstitutionPayoutRequest { amount, reference }`. A body that still carries `payee` answers 422 `payee_not_accepted` before any balance or account check, so an old client fails loudly instead of having its payee silently ignored. With no active account the answer is 422 `no_verified_account`; a pending change keeps T-0623's `account_pending_approval` from the payout service.
- `GET /institutions/{id}/payout-account` answers `InstitutionPayoutAccount { account?: { ibanMasked, holderName }, changePending }`. The full IBAN never leaves the API.
- I09's new-payout screen reads both the balance and the account. It shows "To the institution's own account: {holder} •••• {last4}" above an amount and reference form; with no account, or a change pending, it shows a notice and no form. The submit button now says "Withdraw with passkey".
- The demo seed adds Carl Compliance (`staff-compliance-2`). Cleo runs the KybPort simulator checks for amuta `580123456` instead of recording them by hand, so the identifier check carries the registered name the account is held in. She records the fictional own account and Carl approves it. A yeshiva seeded before this card, checked by hand, gets the automated checks on its next seed run.
