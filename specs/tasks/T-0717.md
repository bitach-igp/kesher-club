# T-0717 [WAL] The mirror queue: a table written with the journal, an idempotent enqueue, a claim with backoff and a dead-letter state, and the `wallet.mirror` flag
REQ: REQ-LED-004, REQ-WAL-002 (after T-0716) · Sprint: later (ADR-018 decision of 2026-11-11, proposed)
Files: db/migrations/ledger/0033_mirror_item.sql (new), db/migrations/ledger/atlas.sum, apps/api/src/mirror/queue.ts (new), apps/api/src/mirror/queue.test.ts (new), config/flags.json, apps/api/src/config.ts (the `funding` entry of the flag map: `wallet.mirror` joins it), apps/api/src/config.test.ts, packages/ports/src/catalogue.ts (the `funding` row cites the flag), handoff/desktop/T-0717-mirror-item-apply.md (new), specs/tasks/T-0717.md, specs/tasks/README.md
Source: ADR-018, M1. The existing outbox is unfit for a vendor drain: it is written by transfer events, not by journals; its one sink ignores other messages; `OutboxPublisher.publishBatch` (`apps/api/src/transfers/outbox.ts`) calls the sink inside the claim transaction; a failing row is retried every 10 s with no backoff, due time or dead-letter (`attempts` is counted, nothing reads it). A new table `ops.mirror_item` is not a ledger table (`club_app` may update it, as for `ops.outbox`, migration 0031).
Assumption: M1 (queue in the journal's transaction, drained by its own job), M2 (a leg has an optional `after` item: leg 2 waits for leg 1), M7 (a due time and a dead-letter state), M4 (a leg is USD only: `amount_minor bigint check (amount_minor > 0)` and `currency text check (currency = 'USD')`).
Test first: TST-LED-003, TST-WAL-003. `enqueue(tx, { journalId, seq, direction, memberAccountRef, amount, afterSeq?, dueBy })` writes one `pending` row keyed `(journal_id, seq)` and derives the Crowded key from it (`{journalKey}:m{seq}`); the same call twice leaves one row; `claim(limit, now)` returns due rows (`next_attempt_at <= now`, `state = 'pending'`) with `for update skip locked`, a row whose `after` item is not `settled` is not returned, and two concurrent claims never return one row twice; `settle`, `retry(error class, now)` and `deadLetter(error class)` move the state, `retry` sets `next_attempt_at` by exponential backoff (30 s, doubling, capped at 15 min, no jitter in tests: the clock is injected) and counts `attempts`, a row past `max_attempts` or past `due_by` (the same-day cutoff) is `dead` and is no longer claimed; `unmirrored(partyId)` returns the sum of `amount_minor` of that member's rows not `settled`; `unmirroredTotal()` the same for all; amounts are `bigint` and a leg of zero, negative or in ILS is refused by the table and by `enqueue`; nothing in a row, log line or error carries a name, email or mobile (only refs, key and amount); `wallet.mirror` is in `config/flags.json` with `defaultProd: false` and the catalogue test (flags cited exist) and `config.test.ts` (a gated flag on a simulator port is refused in prod) pass with it.
- Columns: `id bigint identity`, `journal_id uuid not null`, `seq smallint not null`, `kind text`, `direction text check in ('to_checking','from_checking')`, `member_party_id uuid`, `amount_minor bigint`, `currency text`, `idempotency_key text unique`, `after_seq smallint null`, `state text check in ('pending','settled','dead')`, `attempts int`, `last_error_class text`, `next_attempt_at timestamptz`, `due_by timestamptz`, `created_at`, `settled_at`; unique `(journal_id, seq)`; index on `(state, next_attempt_at)` and on `member_party_id` where not settled. The Crowded account ref of the member is NOT a column: it is read from `ops.external_ref` at drain time (CLAUDE.md).
- The migration is forward-only; no constraint is added `VALID` over existing rows (the table is new). Run `atlas migrate hash --dir file://db/migrations/ledger`, then `pnpm db:lint`. The real Postgres apply is a request in `handoff/desktop/` per `handoff/README.md`, each statement the next depends on in its own `psql -c`.
