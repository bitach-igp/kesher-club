Test first: TST-PAY-008 (screen rows).
- The screen asks for a first name and a last name, and says plainly that people paying the member see only "Avi E.".
- It checks the name the way the API does before saving, and shows the API's refusal in words.
- Home's settings card gains "Your name" under "Receive money in", reading "Not set" until the member sets one.

The tests cover:
- saving "Avi" and "Example" shows "Avi E.";
- a name with digits is refused before the call;
- an API refusal shows as words;
- the Home row routes to the screen and reads "Not set" until a name is saved.

Done when: listed tests pass; `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm trace` green; only listed files touched
Out of scope: asking for the name during sign-up (Tab 2 decides onboarding). Stop and ask on conflict with the spec.

As built:
- **The "Your name" screen.** It lives at `app/settings/name.tsx`, route `/settings/name`, with the model in `name.model.ts`.
  - The screen shows "People paying you will see: Avi E." as the member types.
  - `checkName` holds the API's rule: letters in any script, with spaces, hyphens, apostrophes and Hebrew geresh or gershayim, starting with a letter; at most 40 for the first name and 80 for the last.
  - A refusal from the API lands on the field it names. Any other failure says so and keeps what was typed.
- **Reopening the screen.** It fills in the first name only. The last name was never stored (T-0531), so it starts empty.
- **The Home row.** Home loads the name beside the balances. "Your name" reads the name, or "Not set" when it is unset or the call fails; the balances never wait on it. The row sits under "Receive money in" on the same card.
- **The API client.** `DisplayNameApi` sends a last name only when one is typed.
- **Copy.** English and Hebrew are mirrored.
