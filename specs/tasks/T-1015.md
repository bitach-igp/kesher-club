# T-1015 [AGT] Authorization server, part 2: the member's consent creates the grant and a one-time code
REQ: REQ-AGT-010, REQ-AGT-008 (after T-1014) · Sprint: 13
Files: apps/api/src/oauth/consent.ts, apps/api/src/oauth/consent.test.ts, apps/api/src/app.ts, contracts/openapi.yaml, packages/sdk/src/schema.generated.ts, specs/tasks/T-1015.md, specs/tasks/README.md; shared plumbing: apps/api/src/routes.ts, packages/sdk/src/client.ts (HEADER_OPS)
Test first: TST-AGT-010 (consent rows). All three calls use the member's bearer, behind `mcp.enabled`:
- `GET /oauth/requests/{id}`: the client's name and home page, each requested scope with its tier, and when the request expires.
- `POST /oauth/requests/{id}/approve`:
  - needs a fresh step-up, and takes the scopes the member kept (a subset of those asked);
  - creates the grant, or replaces the scopes of the member's active grant for that client;
  - issues a one-time code valid for 60 seconds, stored as a hash and bound to the client, redirect URI, PKCE challenge and resource;
  - answers the redirect URL with `code` and `state`.
- `POST /oauth/requests/{id}/deny`: answers the redirect URL with `error=access_denied` and `state`.

A request is decided once, and only by a member while it is still open.

The tests cover:
- approve without a step-up answers STEP_UP_REQUIRED;
- approve with two of three scopes creates a grant with those two, and a second approval for the same client updates that grant;
- an expired or decided request answers 409;
- another member's request answers 404;
- deny returns `access_denied`;
- the code is stored only as a hash.
