Test first: `packages/domain/src/config.ts:74` refuses `sim` outright when `APP_ENV=prod`, which makes a pilot deploy with the money flags off impossible: card issuing, KYC, FX and payouts have no vendor yet (ADR-006) and would need a simulator. Replace the blanket refusal by: in prod a port may stay on its simulator only if every flag it gates is false in `config/flags.json` and in the flag store; the process refuses to start otherwise, naming the port and the flag. Turning such a flag on later is refused by the existing release gate (T-0902) while the port is a simulator. Tests: prod with the card port on a simulator and `cards.*` off boots; the same with a card flag on refuses; a flag flipped on at runtime for a simulator port is refused.

## As-built
- `PORT_FLAGS` (apps/api/src/config.ts) maps each simulator capability to the flags its vendor backs; ports with no row (auth, notify, events) gate nothing. The blanket prod refusal in `packages/domain/src/config.ts` is gone. `assertProdSimulatorsSafe` runs at API and worker boot (registry defaults plus `ops.flag_state`), and `FlagService` refuses a flip on (propose and approve) while the port is a simulator (`refuseFlagsOnSimulators`, prod only; 422 `VALIDATION_FAILED`).
- Consequence to know before a prod deploy: `billing.stripe`, `billing.applePay` and `billing.googlePay` default on in prod, and the billing port is still a simulator, so prod will not start until T-0041 binds Stripe or those three are switched off in the flag store.
- `auth.passkey.primary` is not mapped (the auth port has no vendor adapter and the flag is a UI choice); revisit with T-0059.
