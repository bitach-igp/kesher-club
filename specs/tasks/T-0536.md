## As built
- `GET /accounts/{id}/transactions` replaces the FEATURE_OFF stub, read from the ledger itself: each journal that
  posts to the member's own wallet account is one row, so there is no second table to drift. Direction is the
  wallet posting's sign (credit-normal: positive is money out); the amount is always positive.
- A card authorisation (`auth_hold`) is one row: pending, settled once a `card_clearing` names its `authId`, reversed
  once an `auth_release` does; clearings, releases, and load and P2P holds and releases are folded away, not rows. A
  journal that reverses another reads `reversal`; `refund` (closure) reads `payout`; `esim` reads `addon`.
- The `Transaction` schema gains optional `mcc` and `country`, on card rows only. The ledger keeps no merchant text,
  so `counterparty` and `untrusted` stay empty for now.
- The cursor is the last row's time and id (base64url), so rows posted in the same millisecond never repeat or
  drop; `limit` 1–100 is honoured, 50 by default. A cursor this API did not give answers 422.
- `TransactionService.forAccount` is the funder's path too (T-0537), after its own household check.
