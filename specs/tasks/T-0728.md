# T-0728 [WAL] The mirror drain books up to ten independent legs in one Crowded request, never a pair together
REQ: REQ-LED-004, REQ-WAL-002 (after T-0722) · Sprint: later (ADR-018 decision of 2026-11-11, proposed)
Files: apps/worker/src/mirror/drain.ts, apps/worker/src/mirror/drain.test.ts, apps/api/src/mirror/queue.ts, apps/api/src/mirror/queue.test.ts, specs/tasks/T-0728.md, specs/tasks/README.md
Source: ADR-018, M2. Book Payment takes 1 to 10 items per request with continue-on-error (snapshot, line 10654); an allowance run of hundreds of students (`allowance/workflow.ts`, 20 at a time) would otherwise make one request per student. Ordering and atomicity inside one request are not documented, so only legs with no dependency share a request.
Assumption: M2 (items are independent; order unknown), M7 (a batch failure is per item). Unconfirmed: a per-request or per-minute rate limit (README question 39).
Test first: TST-WAL-003, TST-LED-003. 25 pending independent legs drain in three requests of 10, 10 and 5 (the fake counts requests); a leg whose `after` item is not settled is never in the batch with it (a pair takes two requests, in order); one refused item of ten dead-letters or retries only that row and settles the other nine; a whole-request outage retries all ten with backoff and books each once on recovery; an `OUTCOME_UNKNOWN` for the request reads every item back by key before any resend; two workers never batch one row (`skip locked`); `claim` takes a limit and the batch never exceeds 10; the oldest legs go first (by `due_by`, then `id`, not by uuid alone).
