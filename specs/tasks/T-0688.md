## As-built
- Shared plumbing touched: `apps/api/src/app.ts` (one line mounting `webhookHandlers`), `apps/api/src/routes.ts` (6 operations), `HEADER_OPS` in `packages/sdk/src/client.ts` (create, rotate and replay carry an Idempotency-Key, no step-up). No migration, error code, flag-default or worker change; `README.md` needed no edit.
- Routes: the five in the card plus `GET /institutions/{id}/webhook-deliveries` (`listWebhookDeliveries`), because the test-first line asks staff to see delivery attempts and no listed route returned them. The flag `webhooks.outbound` is read by every handler (after the role check, before institution scoping): off answers `FEATURE_OFF` 404.
- Roles: create, rotate and delete are institution admins only (403 for staff and finance); list endpoints and list deliveries are any active staff of the institution; another institution's staff get 404 (institution or endpoint id), and a deleted endpoint is 404. Replay is a staff-token (`admin`) call with an Idempotency-Key: body `{ endpointId }`, path id is the message id; the endpoint must be a live endpoint of the message's institution. The Idempotency-Key now feeds the port key (`replay:{message}:{endpoint}:{by}:{key}`), so a repeat answers the same attempt; without a key (service callers) each call is a new attempt as before. Create and rotate derive the port key from the Idempotency-Key too, so a repeat answers the same endpoint and secret (a replayed 201, not a second secret).
- Secret: returned in the create and rotate responses only; not in `notify.outbound_endpoint`, the audit payload, the list, or any log (the tests grep the table and audit rows).
- PATCH supports only `{ "rotateSecret": true }`: the port has no update-event-types call, and the card names no other change. Anything else answers 422.
- DELETE: `EventsPort.deleteEndpoint(endpointId, idempotencyKey)` deactivates at the provider; the simulator then skips the endpoint in `send` and its retries, and `replay` and `rotateSecret` answer `UNKNOWN_ENDPOINT`; the call is idempotent. The contract suite has a case for all of it (the simulator is its only consumer). `OutboundEventsService.deleteEndpoint` calls the port first and then sets `active = false` (the table grants no delete), so a port failure leaves the endpoint live and the call retriable. The earlier "skip when no live endpoint" guard is gone: the port is the source of truth. Tests: two endpoints, delete one, only the other receives; delete the only one, create a new one, the deleted one is not resurrected.
- SSRF: `createEndpoint` only checked the `https://` prefix. `assertPublicHttpsUrl` now requires a parseable https URL of at most 2048 characters, no credentials, port 443 only, no IP literal (IPv4 in any form including decimal and hex, IPv6), at least two labels, and no `localhost`, `.local`, `.internal`, `.lan`, `.home`, `.corp`, `.intranet`, `.home.arpa` name. A public name that resolves to a private address (DNS rebinding) is the delivery provider's to block; it is not checked here.
- The URL is stored and sent to the port in its normalised form (`URL.href`). A reused Idempotency-Key with a different URL or event types answers 409 `IDEMPOTENCY_CONFLICT`.
- Not done, by the card: no dead-letter or attempts rule for a poison outbox message (T-0687 left it to a later card; this card's replay is per delivery), and no console screen. Rotation does not require a step-up (the card names none); say so if the owner wants one.
