# T-0724 [WAL] The unmirrored-exposure cap: a per-member and a total limit with no default, fail closed with PROVIDER_UNAVAILABLE for journals that start a movement
REQ: REQ-LED-004, REQ-WAL-002 (after T-0716, T-0717, T-0721, T-0722) · Sprint: later (ADR-018 decision of 2026-11-11, proposed)
Files: apps/api/src/mirror/exposure.ts (new), apps/api/src/mirror/exposure.test.ts (new), apps/api/src/config.ts, apps/api/src/config.test.ts, apps/api/src/app.ts (shared composition root: `beforePost` installed when `wallet.mirror` is on), specs/tasks/T-0724.md, specs/tasks/README.md
Source: ADR-018, M7. While Crowded is down the queue grows; wallets keep working up to a cap, then new movements fail closed. The guard runs in `beforePost` (T-0716), under the same locks as the posting, so two requests cannot both pass the last cents. It counts `ops.mirror_item` rows not `settled` for the member (and in total), plus the journal's own legs.
Assumption: M7 (configuration with no default; the 'no fallback' rule), M1 (Design B), M4 (only USD legs are counted).
Test first: TST-WAL-003, TST-LED-003. `MIRROR_MAX_UNMIRRORED_MEMBER_MINOR`, `MIRROR_MAX_UNMIRRORED_TOTAL_MINOR` (positive integers, USD cents, parsed as `bigint`) and `MIRROR_CUTOFF_UTC` (`HH:MM`) have no default: with `wallet.mirror` on and any missing or malformed, boot refuses naming only the missing key, never a value; with the flag off they are not read; a `p2p`, `auth_hold` approval, `fee`, `addon`, `fx`, `allowance` or `payout` journal that would take a member's unmirrored amount over the member cap, or the total over the total cap, is refused before the write with `PROVIDER_UNAVAILABLE` (HTTP 503) and `extra: { reason: 'MIRROR_EXPOSURE_CAP' }`, nothing is posted and no transfer is left half-made (the send stays `submitted` for a retry with the same key, like an outage); exactly at the cap passes, one cent over refuses (bigint boundary test); a journal that records something already done in the world is NEVER refused by the cap: `card_clearing`, `auth_release`, a load settling or releasing, a `reversal`, a repair (`{key}:repair`): it posts, its legs queue, and the gauge `mirror.over_cap` rises so an alert fires (a table-driven test over every kind in the ADR inventory says which side it is on, so a new kind with no entry fails the test); a hold inside one member (net zero) is not counted; two parallel journals for one member whose sum exceeds the cap: exactly one posts; legs that settle free room at once (the next journal passes); with the drain stopped and the cap reached for a member, other members still move.
- Counts absolute amounts of legs not settled (debit and credit legs together), so a credit waiting to reach Crowded counts as much as a debit.
Done when: listed tests pass; `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm trace` green; only listed files touched
Out of scope: choosing the numbers (the owner or Ezra sets them per environment); the copy the member sees; the card-specific decline mapping (T-0725); the float check on checking (T-0729).
