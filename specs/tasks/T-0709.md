# T-0709 [WAL] PROVIDER_FUNDING can be `crowded`: config keys, one composite funding binding, memberChapterId into both processes, and the production-guard tests

Source: ADR-018, T-0041 (how Stripe was bound) and T-0043 (the guard). Verified 2026-11-12 at 90fe882; what the first version of this card got wrong or left out:
1. Three classes, not one adapter. `CrowdedFunding` (funding.ts), `CrowdedMemberAccounts` (member-accounts.ts) and `CrowdedMirror` (mirror.ts) are separate classes, and the registry resolves ONE object per capability and finds extra capabilities by checking methods exist. The binding is therefore a small composite built in `binding.ts` that delegates the `FundingPort` methods to `CrowdedFunding`, `ensureAccount, account, chapter, transactions` to `CrowdedMemberAccounts`, `creditWallet` to `CrowdedFunding`, and the six mirror methods to `CrowdedMirror`; `isFundingAccountPort`, `isFundingCreditPort` and `isMirrorPort` are all true on what `registry.resolve('funding')` returns, and still true after the `meterResolve` proxy (`registry.ts`, methods are preserved).
2. Constructor options the card did not list. `CrowdedFunding` requires `hmacKey` (32+ characters), `achHoldDays`, `redirectHosts` (at least one bare host) and wants a persistent `ledger`; `CrowdedMemberAccounts` requires `hmacKey` and a ledger; T-0741 adds `fundHolding`. So the key set is: shared `CROWDED_BASE_URL`, `CROWDED_API_TOKEN`, `CROWDED_WEBHOOK_SECRETS`; funding-only `CROWDED_MEMBER_CHAPTER_ID`, `CROWDED_ACH_HOLD_DAYS`, `CROWDED_FUND_HOLDING` (`true` or `false`, no default), `CROWDED_FUNDING_HMAC_KEY` (secret, 32+ characters, never logged, distinct from the PII keys) and `CROWDED_REDIRECT_HOSTS` (comma-separated bare lower-case hosts, our own app and web hosts). The ledger is `PostgresVendorKeyLedger(db, 'crowded', now)` (`apps/api/src/institutions/crowded-keys.ts`), scoped so the funding keys (`load:*`) and the member keys cannot collide with the institution ones.
3. The shared-key trap. `PROVIDER_PORTS` triggers an all-or-nothing set when ANY key of it is present (`processRules`, `missingProviderKeys`). The three shared keys are already the `institution-banking` set, so a naive funding row would make every institution-banking-only config demand `CROWDED_MEMBER_CHAPTER_ID` and fail to boot. The funding set is triggered only by `PROVIDER_FUNDING=crowded` or by one of its FUNDING-ONLY keys; the shared three are required when it is chosen. Existing institution-banking config tests pass unchanged.
4. `memberChapterId` was never wired. `crowdedMemberChapterId` is an `AppOptions` field (`app.ts:136`) that nothing sets; both `apps/api/src/main.ts` (line 57 area) and `apps/worker/src/main.ts` (the webhook-replay job runs `CrowdedWebhook.process` in the worker) pass `createApp` options and must pass it, or member payment events are treated as institution events and the replay never applies them. The old card listed neither file. A T-0703 review note carried here: it must be set before `wallet.enabled` goes on.
5. The mirror parts are cut. The old card made `CROWDED_CHECKING_ACCOUNT_ID` required "when `wallet.mirror` is on" and asserted a prod refusal tied to the flag list of T-0717. `wallet.mirror` does not exist in `config/flags.json` (T-0717 creates it, and T-0717 to T-0724 wait on D1), and `CrowdedMirror` finds the checking account itself (`checking()` lists the chapter's accounts), so none of that is testable or needed for self top-ups. It moves to T-0717 and T-0724. The composite still carries the mirror methods, with no flag logic.
6. T-0043 guard and billing: kept as the old card said (the refusal is correct and is not worked around), and decided in T-0736 (owner decision 2026-11-12: billing waived, the three billing flags default off). This card only asserts the refusal while they are on.
7. File list gaps closed: `binding.ts` (new), `index.ts`, both `main.ts` and their tests. Terraform and the two setup docs moved to T-0739 (the CI terraform job is a separate check and no `terraform` binary exists in planning sessions).
Assumption: A9 (billing is out of scope and its own decision, T-0736), A1 and A4 (chapter and hold days are configuration).
