Design agreed for it (the rules below, made concrete): the state is stored hashed in `ops.workflow_marker` (kind `sso_state`, the SHA-256 in `claim`, the value holds the institution, the mode, the party for `link`, the device id, the session id, the browser-binding hash and the expiry) and consumed by a write-once `sso_state_used` marker, so a replay or a concurrent double submit has exactly one winner and no migration is needed; the browser binding is an `HttpOnly; Secure; SameSite=Lax` `__Host-` cookie set by `start`; a `link` state lives 5 minutes (the step-up's own window), a `sign_in` state 10; the `link` proof is a fresh `X-Step-Up` or an invite token of THIS institution (accepted at start through `InstitutionTeam.accept`); every identity refusal runs the same reads and answers one 401 body. The WorkOS adapter keeps its own state in memory per process, so the real flow needs one API process until T-1116's follow-up moves it (note in the PR).
Source: decision on T-0785 (2026-11-23). Regenerate with `pnpm --filter @kesher/sdk generate` and lint with `npx --yes @stoplight/spectral-cli@6.15.0 lint contracts/openapi.yaml --ruleset .spectral.yaml`.
Behaviour (rules a reviewer checks): the callback verifies the state (single use, bound to the starting session, 10-minute expiry) and the code through the port; the IdP identity must be linked to an ACTIVE staff row of that institution, or be an invite acceptance in progress (T-0643's `accept`); the link is created only for a party who has just proved control of the Kesher account in the same flow (step-up or the invite token), never by email match; a signed-in SSO session issues the normal staff token (no longer-lived token, no new role); a deprovisioned or unlinked identity is refused 401 with no hint which; the IdP's claims (name, email, groups) are untrusted and never grant a role.
Test first: TST-AUTH-008, simulator org IdP: (1) start returns a URL and a state; the callback with the right state and a linked identity issues a staff token; (2) a wrong or replayed state answers 401; (3) an unlinked identity without an invite is refused and no link is written; (4) after T-0790's deprovision the same identity is refused at the callback; (5) `auth.orgSso` off answers 404 `FEATURE_OFF` on both routes; (6) a group claim naming an admin role does not raise the role.
