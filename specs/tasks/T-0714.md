# T-0714 [WAL] POST /loads accepts a hosted method, answers with the payment-page action, and a load can be read back
REQ: REQ-WAL-002, REQ-WAL-003 (after T-0705, T-0709) · Sprint: later (ADR-018, proposed)
Files: contracts/openapi.yaml, contracts/oasdiff-ignore.txt (only if oasdiff reports a break), apps/api/src/routes.ts (shared plumbing: the new GET operation), packages/sdk/src/client.ts (the hand-kept `HEADER_OPS` table: a GET needs no entry, said so in the PR), packages/sdk/src (regenerated by `pnpm --filter @kesher/sdk generate`), apps/api/src/wallet/loads.ts, apps/api/src/wallet/loads.test.ts, apps/api/src/wallet/handlers.ts, specs/tasks/T-0714.md, specs/tasks/README.md
Source: ADR-018 and the `club-openapi` skill. Checked in the code: `POST /loads` is the only loads operation (there is no read-one route), and the app has nothing to poll while a hosted payment is pending, so this card adds one. `LoadView` returns `clientSecret` for Stripe's sheet; a hosted load returns a page to open. Both `Load` schemas in the contract list `state` and `clientSecret` today.
Assumption: A8 (the response carries `action`), A3 (the page needs the payer's IP and consent: the API takes the IP from the request, never from the body, and consent from an explicit field).
Test first: TST-WAL-002. `POST /loads` with `method: 'hosted'`, an amount, a purse and a body `consent: true` on a simulator that answers `requires_action` returns 201 (or 200 on a replay of the same key) with `state: 'requires_action'` and `action: { type: 'payment_page', url }` and no `clientSecret`; the payer IP the vendor receives is `clientIp(req)`, not a body field (absent means 422); `consent` missing or false is 422 `VALIDATION_FAILED` before any vendor call; the same Idempotency-Key replays the same load and action; a hosted load needs `wallet.enabled` and `funding.ach` (404 `FEATURE_OFF` when either is off, naming which); `action.url` is only ever `https`, and a vendor answer with another scheme is `PROVIDER_UNAVAILABLE`; the response is bigint-safe Money like the rest; a card load through Stripe's simulator returns exactly what it returns today (existing tests unchanged); a new `GET /loads/{id}` (operationId `getLoad`) returns the payer's own load, 404 for anyone else's, re-reads the vendor while the load is `requires_action` or `processing` (through `applyVendorLoad`, T-0703) and returns the action again while the page is still open.
- Contract: the `Load` response gains optional `action` (a `LoadAction` schema: `type` enum `payment_page`, `url` string, `expiresAt` date-time) and the request `method` enum gains `hosted` with a required `consent` boolean when it is `hosted`. Adding optional response fields and an enum value on a request are not breaking for existing clients; if `oasdiff` still reports a change, an entry goes in `contracts/oasdiff-ignore.txt` with this card's id and why no client breaks. Lint with the `spectral` command in CLAUDE.md.
- `LoadService.request()` passes `hosted: { payerIp, userConsented: true }` to the port and `view()` maps the vendor `action` through. The webhook payload still drops secrets (the action url is not stored beyond the vendor's own).
Done when: listed tests pass; `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm trace` green; the OpenAPI lint and the oasdiff job pass; routes still equal the OpenAPI operations; only listed files touched
Out of scope: the app (T-0715); other routes; the embedded token; MCP tools for loads (T-1009 already runs the member's own load path).
