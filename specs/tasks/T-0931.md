## As built
- **One file moved.** Next.js refuses a `route.ts` beside a `page.tsx` in one segment, so the case's actions post to
  `apps/admin/app/ops/[caseId]/actions/route.ts` instead of the listed `app/ops/[caseId]/route.ts` (`next build` checked).
- **Recording from the case.** The deposit form lives on the case page, not the institution page: the amount, rail,
  bank reference and value date are shown, not typed, and the action route takes them from the case again, so a
  forged form changes nothing; finance choose the institution (preselected when the feed matched one) and may add a
  note. `DepositInput.caseId` carries the case to `recordDeposit`, and the API refuses any field that differs (T-0631).
- **Actions.** Support acts on nothing; a decided case offers nothing; a suspense credit is never offered Resolve
  (the API answers 422), only Dismiss, and Record to finance; Assign is hidden once the case is the viewer's.
- **Queue.** Grouped by kind, money with no owner first; filters for kind, status and "assigned to me" ride the
  query string; the HTTP binding reads up to four pages of 50. The nav gains `A12 Ops queue`.
- **Memory binding.** Seeds a ₪5,000.00 suspense credit and a balance break, and follows the API: recording links
  the case, approval resolves it naming the deposit, rejection unlinks it.
