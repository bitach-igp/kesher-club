# T-0620 [INS] KYB over HTTP: the record, people, check dispositions and decisions under /admin
REQ: REQ-INS-011 (after T-0619) · Sprint: 12
Files: contracts/openapi.yaml, packages/sdk/src/schema.generated.ts, packages/sdk/src/client.ts, apps/api/src/institutions/kyb-handlers.ts, apps/api/src/institutions/kyb-handlers.test.ts, specs/tasks/T-0620.md, specs/tasks/README.md; shared plumbing: apps/api/src/app.ts, apps/api/src/routes.ts
Test first: TST-INS-011 (HTTP rows). Endpoints, each on a staff token:
- `GET /admin/institutions/{id}/kyb`: the current decision, the people, the latest check of each kind and person, and the open approval;
- `POST /admin/institutions/{id}/kyb/people`: add a board member, control person or signatory, keyed by an Idempotency-Key;
- `POST /admin/kyb/checks/{id}/dispose`: a false positive or a true match, with a note;
- `POST /admin/institutions/{id}/kyb/decisions`: an outcome, a risk rating and reasons, keyed;
- `POST /admin/kyb/decisions/{id}/approve`: the second reviewer.

Compliance and admin roles write; support reads. Names are staff-entered text, and phone numbers never appear. The tests cover the T-0619 rules over HTTP, including that a support token cannot decide and that a replayed key returns the same row.
Done when: listed tests pass; Spectral clean; `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm trace` green; only listed files touched
Out of scope: document upload (statements and protocols stay with compliance until a document store is chosen). Stop and ask on conflict with the spec.

As built:
- Writes take the `compliance` role, not `admin`: every staff token carries `admin` (the verifier adds it), so "compliance and admin write" would have meant any staff member. Support reads.
- `POST /admin/institutions/{id}/kyb/checks` records a check compliance made by hand (provider `compliance`), or an exception with its reason. The card's list was missing it, and M1 to M4 of the research need it. An excepted sanctions or PEP check still blocks, as T-0619 holds.
- The refusal of an approval answers 422 `VALIDATION_FAILED` with `blocking` in the problem body. Each code is one stable reason, for the console (T-0926).
