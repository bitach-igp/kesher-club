- The port is for a US account held for an institution at a provider: by the institution's own US entity (`holder: 'institution'`), or by the platform's company, Israel Global Pay, LLC, with the institution as a sub-account or a ledger share (`holder: 'platform'`). See the setups table in `docs/vendors/crowded/README.md`. It never holds a member's balance. Direction `out+in`, capability `institution-banking`, flag `institutions.usBanking`, vendors `['crowded']`.
- Methods, all keyed by our ids with the provider's ids returned for `ops.external_ref`:
  `createEntity({ holder, institutionId, legalName, ein, idempotencyKey })` (for `platform`, one entity for us and one sub-unit per institution: `createSubAccount({ entityRef, institutionId, idempotencyKey })` → `{ subAccountRef, hasOwnAccountNumber }`), `startApplication({ entityRef, applicantIp })` → `{ formUrl }`,
  `applicationStatus(entityRef)` → `'pending' | 'approved' | 'rejected' | 'needs_info'`, `account(entityRef)` → `{ accountRef, balance: Money, last4 }` (never the full number),
  `createCollection({ entityRef, title, amount: Money, idempotencyKey })`, `createPaymentPage({ collectionRef, funder: { name, email, mobile }, idempotencyKey })` → `{ intentRef, paymentUrl }`,
  `collectPayments({ entityRef, since })` async iterator, `quoteAch({ entityRef, amount })`, `sendAch({ entityRef, counterpartyRef, amount, addenda, idempotencyKey })`, `achStatus(paymentRef)`,
  `cancelAch(paymentRef)`, `bookTransfer({ fromRef, toRef, amount, memo, idempotencyKey })` (between our own sub-accounts in the platform setup), `transactions({ entityRef, from, to })` async iterator, `parseWebhook(headers, rawBody)` → `{ events: InboundEvent[] } | { rejected: reason }`.
- `Money` is USD only: any other currency throws before the provider is called. `addenda` is at most 80 printable ASCII characters.
- Simulator fixtures choose outcomes: `holder_platform_subaccounts`, `holder_platform_pooled` (no per-institution account numbers), `ent_ok`, `ent_rejected`, `ent_needs_info`; `pay_ok`, `pay_declined`, `pay_refunded`; `ach_ok`, `ach_returned`, `ach_rejected_201` (a create that answers 201 with status Rejected), `wh_bad_sig`, `wh_dup` (the same eventId twice in one batch).
**Tests.** the suite passes against the simulator; the same idempotency key returns the same object; a reused key with another body fails; transaction iteration across pages yields each row once; catalogue has 21 ports and its test counts them; both platform fixtures and the institution holder pass the same suite.

## As built
- **Port.** `InstitutionBankingPort` as the card lists it, direction `out+in`, capability `institution-banking`, flag
  `institutions.usBanking` (already in `config/flags.json`, default off, so no flag change), vendors `['crowded']`.
  USD only through `requireUsd` (also refuses zero and negative); `addenda` through `isAddenda` (at most 80 printable
  ASCII). `parseWebhook` answers `{ events } | { rejected: 'BAD_SIGNATURE' | 'MALFORMED' }` and passes a duplicate
  event id through, since `ops.inbound_event` dedupes by (provider, eventId). Error codes: `VALIDATION_FAILED`,
  `PROVIDER_UNAVAILABLE`, `NOT_FOUND`, `NOT_APPROVED`, `IDEMPOTENCY_CONFLICT`, `NOT_CANCELLABLE`, `REJECTED` (the
  201-with-Rejected case).
- **Simulator.** Fixtures pick outcomes by the start of a text input: `ent_*` by legal name, `pay_*` by funder name,
  `ach_*` by counterparty; `OUTAGE` legal name is the unavailable case. Control hooks `decide`, `pay`, `settleAch`,
  `post`, `webhook` (with `wh_bad_sig` / `wh_dup`). The constructor takes a page size so tests cross page boundaries.
- **Shared files outside the card's list, touched only for the new count:** `apps/api/src/admin/handlers.test.ts` (20
  → 21 ports) and a comment in `apps/admin/src/providers/release-gates.test.ts`. `apps/simulators/src/host.test.ts`
  needed no change: it counts `PORTS.length`.
- **Second PR (Ezra's 2026-11-02 update).** `createEntity` takes `holder: 'platform' | 'institution'`; a platform entity
  has `createSubAccount` → `{ subAccountRef, hasOwnAccountNumber }` and `bookTransfer` between the platform's own
  accounts (once per key, never overdrawing, `memo` as `addenda`). With `holder_platform_pooled` the unit has no
  account of its own: reading it, sending from it or booking to it is VALIDATION_FAILED, and the money is tracked in
  our ledger (T-0653). The contract suite runs under all three setups (institution, platform with sub-accounts,
  platform pooled); the holder-specific cases skip under the others.
- `quoteAch` returns `arrivesOn` only where the provider says (Crowded documents no arrival date), so it is optional.
- `institutionBankingContract` is now exported from `packages/ports/src/contracts.ts`, as every other contract is, so
  an adapter's contract test can import it from `@kesher/ports/contracts` (T-0648). One line, outside the card's list.
- The card's file list also carries the docs commit from `cards/crowded-integration` (the inventory, REQ-INS-022..026
  and cards T-0647..T-0655), brought in as its own commit so `pnpm trace` knows the REQs.
