# T-0648 [INS] Crowded adapter for InstitutionBankingPort
REQ: REQ-INS-022, REQ-INS-024 (after T-0647) · Sprint: later (P3, flag `institutions.usBanking`)

- `client.ts`: base URL from config (sandbox `https://sandbox-api.crowdedfinance.com/api/v1`; no production default), bearer token from the secret store, 15 s timeout, unwraps the `data` envelope, pages with `limit`/`offset` until a short page.
- Errors map to the closed set: 401/403 → provider auth error logged and `PROVIDER_UNAVAILABLE`; 404 → not found; 422/400 → validation with the provider's message kept as data; 429 and 5xx → `PROVIDER_UNAVAILABLE`, retried by the caller's workflow, never in the client. A 201 whose body says `status: "Rejected"` is a failure, and so is any per-item error in a bulk 200.
- `map.ts`: integer cents ↔ `Money { minor: bigint }` (reject non-integers and non-USD), every id to a string, one table for enum casing (`Cancelled`/`canceled`, `Card`/`card`, …), ISO timestamps to `Date`.
- Creates with a body `idempotencyKey` send our key (a UUIDv5 of our workflow key when it isn't a UUID). Creates without one (organization, chapter, contact, collection) look the object up by our external ref first and create only when absent.
- Never log or return `accountNumber`, SSNs, dates of birth or officer details; `account()` returns last four only.
- `sandbox.test.ts` runs only when `CROWDED_SANDBOX_TOKEN` is set and is skipped otherwise.
**Tests.** the contract suite passes on the fake; cents round-trip for 0, 1 and 2^53+1; a 201 Rejected maps to a failure; a lookup-before-create retry makes no second organization; logs contain no account number.

## As built
- **Where.** `packages/adapters/src/crowded/`: `client.ts` (base URL and token passed in, https only, 15 s timeout, `data`
  envelope unwrapped, lists page to `meta.pagination.total` or a short page, no retries, token in a closure),
  `map.ts` (cents ↔ `Money`, ids as strings, enum tables, `last4`, name split, UUIDv5 of our keys, refs),
  `institution-banking.ts` (the adapter, `KeyLedger`), `fake-crowded.ts` (an in-process Crowded API), tests, and an
  `index.ts` (outside the card's list; the package exports one per vendor).
- **Refs.** An entity is a chapter id (a sub-account is a chapter too). Objects Crowded addresses under a chapter are
  `<chapter>:<id>[:<id>]`: collection, intent, ACH payment, transaction. They are opaque to callers (for `ops.external_ref`).
- **Creates with no key** (organization, chapter, collection): look up by exact name first (`GET /organizations?search=`,
  `/chapters?search=&filter[organizationId]=`, `/chapters/{id}/collections?search=`), create only when absent, and a
  `KeyLedger` remembers key → result and body (same key, other body: `IDEMPOTENCY_CONFLICT`). The default ledger is in
  memory; **T-0650 must wire one that persists**, or a restart between two creates relies on the name lookup alone. A new
  key with an existing legal name reuses that organization and chapter. The shared contract's "another key is another
  entity" case now uses another name (one line in `institution-banking.contract.ts`). Creates that take a key (sub-accounts,
  ACH, funding) send a UUIDv5 of ours.
- **Decisions where the port and Crowded differ** (Q numbers are the vendor README's):
  - `quoteAch` returns no `arrivesOn` (none documented). `AchStatus` never reaches `settled`: `sent` is as far as it goes
    (`processing` reads as `pending`; `canceled` as `cancelled`; `failed` as `rejected`). A 201 with status `Rejected` is
    `REJECTED`, as is a per-item error.
  - `collectPayments` yields outcomes only (`Succeeded` → `paid`; `Failed`/`Cancelled`/`Returned` → `declined`;
    `Refunded` → `refunded`); pending and processing are skipped. Its `amount` is Crowded's `amount` less `fee` where
    `feeCovered` (Q13: gross or net is unconfirmed). A later return of a paid ACH reads as `declined` on the next read.
  - A payment intent needs `payerIp` and `userConsented: true`. The port has neither, and an adapter must not assert consent
    for a person, so the caller passes `payer` in the options or `createPaymentPage` refuses (`VALIDATION_FAILED`, nothing sent).
    **T-0652 must decide where the IP and consent come from.**
  - `quoteAch` needs a saved counterparty: `collectionCounterpartyRef` (Kesher's collection account, set up by ops). A
    sub-account needs a contact: `subAccountEmail`.
  - `bookTransfer` goes parent → sub-account through `POST /subaccounts/fund` (its response is undocumented: any item with
    an error or a failed status is a refusal). Crowded's book payments are checking ↔ contact accounts, so a sub-account → parent
    transfer is refused locally. Hosted-form IP is the applicant's (`contactIp`).
  - Every Crowded sub-account has its own deposit account, so `hasOwnAccountNumber` is always true; the pooled setup is not
    something Crowded offers (the contract suite is run for the institution holder and the platform holder).
  - `createEntity`'s `ein` is checked but not sent: Crowded's chapter has no EIN field, the hosted application collects it.
    A funder's name is split at its last space; the transaction `description` is Crowded's `title`.
  - Request bodies are wrapped in `data` everywhere (the global rule); the docs are inconsistent for quotes and
    sub-accounts, so the sandbox is the check (Q15).
- **Webhooks.** `parseWebhook` splits the batched envelope (`eventId`, `eventType`, `timestamp`) and names the object by our ref
  (`<chapter>` for applications, `<chapter>:<id>` for payments). The signature check is a function the caller passes
  (`verifyWebhookSignature`), because the HMAC verifier is T-0649: **with none, every webhook is refused.**
- **Never returned or logged:** the account number (last four only, tested against the fake's real number), names, emails,
  mobiles, the token (also tested). Provider messages are kept as data, cut to 200 characters. A 401/403 calls
  `onAuthFailure(status)` and reads as `PROVIDER_UNAVAILABLE`.
- **Not run:** the contract suite against the real sandbox. Approving a bank application takes a person, so
  `sandbox.test.ts` is a read-only smoke test, skipped without `CROWDED_SANDBOX_TOKEN` (it also reads `CROWDED_BASE_URL`).
