Test first: TST-INS-025.
- Route `POST /v1/webhooks/crowded` (OpenAPI first, `club-openapi`). Answers 404 `FEATURE_OFF` when the flag is off, 401 on a bad signature (row in `ops.inbound_rejected`), otherwise 200 fast.
- Verify `X-Webhook-Signature: sha256=<hex>` as HMAC-SHA256 of the **raw request bytes** with the endpoint secret, constant-time compare, before any JSON parse. Keep a second secret slot for rotation.
- Split the batched envelope; insert each event into `ops.inbound_event` keyed by (`crowded`, `eventId`); a duplicate is a no-op. Unknown event types are stored and ignored.
- Payment, collection and application events are hints: the handler re-reads the object through the port and acts on the provider's current state, never on the event body. Events arrive unordered and at least once.
- Event bodies are untrusted text: stored and shown as text, never interpreted.
**Tests (TST-INS-025).** a correct signature over the raw bytes passes and the same payload re-serialised with other whitespace fails; a missing or `sha1=` header fails; a batch of three with one duplicate inserts two; an older event after a newer one leaves the state the re-read returned; flag off answers 404.
