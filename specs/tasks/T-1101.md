## As-built (2026-11-27, branch `card/T-1101`)
- Migration `db/migrations/identity/0009_recipient_profile.sql` (header `(enabling)`: the card has no REQ row yet). Two new tables: `identity.recipient_profile` (one current row per member, `club_app` select, insert, update) and `identity.recipient_profile_history` (insert-only: `club_app` select and insert, no update, delete or truncate). `category` is held by an inline check on both tables (new tables, nothing to scan, so no `NOT VALID`). `program` and `israel_connection` are `bytea` sealed by the PII cipher under their column's name; neither is indexed. `atlas.sum` refreshed (the `atlas` CLI is not installed in the cloud session: the hash was recomputed with the documented algorithm and checked to reproduce the existing file byte for byte first; the desktop run re-verifies).
- `apps/api/src/identity/recipient-profile.ts`: `RecipientProfileService` and `recipientProfileHandlers` (`getRecipientProfile`, `updateRecipientProfile`). Order of checks: bearer (401), flag (`FEATURE_OFF` 404), body (`VALIDATION_FAILED` 422). Wired in `apps/api/src/app.ts` and `apps/api/src/routes.ts` (shared plumbing, named in the PR). `HEADER_OPS` is untouched: neither operation takes an idempotency key or a step-up.
- Behaviour. GET answers 200 with `category`, `program`, `israelConnection`, `updatedAt` all `null` while unset (nothing is stored by a read). PATCH is partial: fields left out keep their value; `null` or blank clears `program` and `israelConnection`; `category` cannot be cleared and is required the first time. Free text is NFC-normalised and trimmed, counted in characters (code points) after trimming (80 and 280), and refused when it holds any control, format (bidi, zero-width) or line or paragraph separator character, so the statement is one plain line. An unknown key in the body is refused. The error carries `field`, never the typed text.
- Insert-only trail: the current row and its history row are written in one transaction under `select ... for update`; when the merged values equal the stored ones nothing is written (no history row, `updatedAt` stays the time of the last real change). The history holds its own sealed copy of each answer.
- Not logged: the service has no logger and writes no audit entry (the history table is the trail; an audit payload would have to leave the text out anyway). The test spies on `console`, `stdout` and `stderr` through accepted, control-character, over-length and read calls and reads `audit.entry`, and finds none of the text.
- Flag `phase1.recipientProfile` in `config/flags.json` (default off in production, owner `Kathleen` as the other non-money flags, trigger: owner confirms phase 1 scope in T-1106 and migration 0009 is applied on real Postgres). Not a money flag.
- Contract: `/me/recipient-profile` GET and PATCH, schemas `RecipientCategory` and `RecipientProfile` (null-able fields as `type: [string, "null"]`, new to this file; Spectral clean). The request schema allows 400 and 1400 characters because the server counts after trimming and in characters; the response schemas carry the real 80 and 280. No new error code. SDK regenerated (`schema.generated.ts` only).

- Desktop handoff: `handoff/desktop/T-1101-recipient-profile.md` (apply on postgres:16, grants, check constraints; each dependent statement in its own `psql -c`). Not run yet.
