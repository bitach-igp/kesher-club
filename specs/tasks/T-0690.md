## As-built
- `.github/workflows/sandbox-contract.yml`: cron `17 3 * * *` plus `workflow_dispatch`, no other trigger; top-level `contents: read`, and `issues: write` only on the five port jobs (`stripe`, `twilio`, `postmark`, `expo`, `crowded`), one job per port so a job sees only its own vendor's secrets. Each job gates on its required secrets: missing ones print `::notice` and the job succeeds; otherwise it runs `vitest run <file> -t "<suite>"` (a skipped suite would otherwise pass vacuously). Every job refuses a fork (`!github.event.repository.fork`). On failure `gh issue list` looks for an open issue titled `Sandbox contract failing: <port>`: comment if found, else `gh issue create` (no labels). An `uncovered` job notices the ports that have no sandbox suite (Airalo, Cover Genius, WorkOS, Apple/Google). Actions are `@v4` major tags, as in `ci.yml`.
- Secret names are exactly the variables `sandbox.contract.test.ts` and `crowded/sandbox.test.ts` read, listed in `docs/setup/sandbox-contracts.md`; `packages/adapters/README.md` points to it.
- `tools/release/sandbox-contract-workflow.test.mjs` (node:test, picked up by the root `pnpm test`; the repo has no YAML dependency, so it reads by indentation): triggers, permissions, fork guard, pinning, skip-with-notice and issue dedupe, every referenced secret documented, and the secrets equal the env vars the tests read.
- Not verified: `actionlint` is not installed here, so the workflow was only parsed as YAML and run through the test above; a real run needs the owner's secrets. Not decided (owner): issue labels or assignees, and whether to add sandbox suites for the four uncovered ports.
