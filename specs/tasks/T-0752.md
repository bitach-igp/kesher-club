# T-0752 [WAL] The exempt-purpose guard: a member sub-account is opened only for a stated purpose, behind the flag, through one service
REQ: REQ-WAL-002 (after T-0750, T-0751, T-0738) · Sprint: later (ADR-018 decision of 2026-11-18)
STATUS: BUILD-READY NOW against the simulator (T-0750). The purposes list itself is counsel's (T-0759); this card ships the mechanism and an empty default.
Files: apps/api/src/wallet/sub-accounts.ts (new), apps/api/src/wallet/sub-accounts.test.ts (new), apps/api/src/config.ts and apps/api/src/config.test.ts (one key, `SUB_ACCOUNT_PURPOSES`), specs/tasks/T-0752.md, specs/tasks/README.md
Source: ADR-018 condition 2. This replaces the "ensure the account" half of T-0740 (`ensureAccount` for a wallet). `SubAccountService.open({ partyId, purpose }, now)` reads the member's owner details (T-0738's reader), calls `MemberSubAccountPort.ensureSubAccount` once under the key `funding-subaccount:{partyId}:{purpose}` and writes `ops.external_ref` rows (`funding_subaccount` = `s:<chapter>`, `funding_account` = `s:<chapter>:<account>`, `on conflict do nothing`).
Test first: TST-WAL-002. With `wallet.subAccounts` off, `open` is `FEATURE_OFF` and nothing is called; a purpose that is not in the configured list (`SUB_ACCOUNT_PURPOSES`, a comma list, NO default: an empty list refuses every purpose) is 422 `VALIDATION_FAILED` with `extra { purposeRequired: true }`, before any vendor call or row; an empty purpose is the same; a member with no stored owner details and no invitation email is 422 `VALIDATION_FAILED` with `extra { detailsRequired: true }`; a valid call makes one port call and two refs, and a second `open` for the same member and purpose makes NO port call (the rows are read first) and returns the same refs; a status `frozen` or `closed` is `FEATURE_OFF` naming the status; `ownerStatus: 'failed'` still returns the sub-account but opens ONE `ops.case` of kind `subaccount_owner_failed` (severity medium, dedupe `subaccount-owner:{partyId}`, no personal data in the payload) so staff can re-invite; the refs are never returned in a response; no log line, error or case payload holds a name, mobile or email.
- A member under the age the owner decides (T-0738 owner item I4) gets no sub-account: the service takes an `eligible(partyId)` dependency, default "refuse", so this card cannot open one for a minor by accident.
