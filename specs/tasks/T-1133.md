Source: The independent review of #426: the public sign-in start (`/v1/institutions/*/sso/start`) lets about 2000 unauthenticated starts evict a legitimate in-flight login from the adapter's in-memory state store (a bounded map), and each start costs a WorkOS API call.
Shape: (1) an edge rate rule on the start paths (already owed in the README checklist); (2) a per-institution cap on in-flight logins, so one institution's flood cannot evict another's; (3) the shared state store of T-1118 (an eviction policy that drops the flooder first, or a store with a per-key TTL), so the bound is not per process.
Test first: 2000 starts for one institution do not evict an in-flight login of another; the cap answers the uniform refusal, not a 500.
