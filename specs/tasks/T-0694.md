# T-0694 [AUTH] A member's Apple or Google link is stored, with the Apple refresh token sealed
REQ: REQ-AUTH-004, REQ-AUTH-005 · Sprint: later
Files: db/migrations/identity/0006_federated_token.sql, db/migrations/identity/atlas.sum, handoff/desktop/ (one request), apps/api/src/auth/social-links.ts, apps/api/src/auth/social-links.test.ts, apps/api/src/auth/repository.ts, apps/api/src/auth/pg-repository.ts, specs/tasks/T-0694.md, specs/tasks/README.md
Source: T-0692's design check, 2026-11-10. T-0691 signs a member in through an `ops.external_ref` row (entity_type `member`, provider `apple` or `google`, external_id the IdP subject) but nothing writes that row, and nothing keeps the Apple refresh token that T-0692 must revoke on deletion. `FederatedIdPPort.exchangeCode` can return a `refreshToken`; no caller persists it.
Test first: `SocialLinks.link(partyId, provider, { subject, refreshToken? })` writes the `ops.external_ref` link and, for Apple, the refresh token sealed with `PiiCipher` (AES-256-GCM, the column name as associated data) in a new `identity.federated_token (party_id, provider, refresh_token_sealed bytea not null, created_at, primary key (party_id, provider))`; a second link for the same member and provider is refused (409 `IDEMPOTENCY_CONFLICT`), a subject already linked to another member is refused; the stored token is never plaintext (read the column raw), never logged, and `unlink` deletes both rows; a member with only a Google link has no token row; reading the token back (`takeForRevoke`) decrypts it only for the revoker.
- Forward-only migration, new table only (club-ddl: uuid, timestamptz, `club_app` grants limited to this table); a desktop handoff per `handoff/README.md`.
- A service function only: no route. The settings screen and its route (step-up required, since it adds a sign-in method) are a later card.
Done when: listed tests pass; `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm trace`, `pnpm db:lint` green; desktop handoff PASS; only listed files touched
Out of scope: the link route and screen; Google refresh tokens; revoking (T-0692).
