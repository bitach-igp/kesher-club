Design: `export const isUuidShape = (s: string): boolean => /^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$/i.test(s)` next to `isUuid`, with a doc line saying test fixtures use loose ids and that the strict check is `isUuid`. Each call site changes `UUID.test(x)` to `isUuidShape(x)` and drops the const; `typeof x === 'string' &&` guards stay where they are (the function takes a string).
Test first: No new TST id: every touched module's existing tests stay green (admin TST-ADM-004, p2p, wallet and institution suites). `ids.test.ts` new cases: `isUuidShape` accepts a v7 id, a v4 id, a loose fixture such as `00000000-0000-0000-0000-000000000001` and an upper-case id; rejects a missing hyphen, a trailing newline, a 35 or 37 character string, a non-hex digit; `isUuid('00000000-0000-0000-0000-000000000001')` stays false (the strict check is not loosened). A repo test or lint grep (in `ids.test.ts`, reading `apps/api/src`) fails if a new `const UUID = /^[0-9a-f]{8}-` appears. Every touched module's existing tests pass unchanged.
