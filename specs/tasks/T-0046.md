As built:
- **System accounts only.** `bootstrap.ts` (`run(db, { appEnv, adminEmail })`) creates `fx_position`, `fee_income`, `partner_settlement` and `addon_payable` in USD and ILS (eight), the kinds `systemAccount(` / `findSystemAccount(` read; a test scans the source for new ones. Not `suspense` (an ops case kind), `payout_reserve` (per institution) or `interchange_income` (unused). The key is `ledger.account`'s unique (owner, type, currency); a second run creates nothing. It inserts as `club_app` (tested under that role).
- **Environments.** `staging` and `prod` only; `development`, `test`, `preview`, `production` and unset are refused before any connection opens. `index.ts` runs only as the entry point (the strip-only load test imports it), needs `DATABASE_URL`, and logs JSON lines with no secret and a masked address. Script: `pnpm --filter @kesher/api bootstrap -- --admin-email <addr>`.
- **BLOCKER, first admin not created.** A Kesher admin has no database account (SSO plus a console-signed staff token); T-0924's `staff_grant` grants a member a role at an institution. There is nothing an invite could be, so none is invented. `--admin-email` is required, validated and reported masked; the first admin is added in the identity provider. Needs an owner decision (and a card) if a stored Kesher-admin record is wanted.
- **Legal shells not created.** `legal.document_version` has no draft state; any row is published and live. Reported read-only (count of kinds with a version).
- **Plans.** Nothing to create: an empty `billing.plan` is the A13 starting point. Reported read-only.
- **No audit entry.** `AuditService.record` takes `lock table audit.entry in share row exclusive mode`, which `club_app` (select, insert) is denied (PGlite shows `permission denied for table entry`). That looks like a defect for every audited API action under the real role; outside this card, to be checked on the desktop. The bootstrap writes none.
- **Not verified.** Against a real RDS or ECS: the `run-task` override (container name and working directory are read from `modules/ecs-service` and `apps/api/Dockerfile`, not run), and the run under the real `club_app` password. `docs/setup/bootstrap.md` has the command and the checks.
