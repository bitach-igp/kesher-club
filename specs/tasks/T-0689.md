## As-built
- `createRegistry(mode, clock, overrides, metrics?)`: with a `metrics` sink, `registry.resolve` returns the port behind one `Proxy` (`meterResolve`, `apps/api/src/registry.ts`); every method that throws or rejects with PROVIDER_UNAVAILABLE, or with anything that is not a coded port error (a transport failure, an adapter bug), counts `provider.error{port,provider}` once and rethrows the same error object. A coded answer (BAD_SIGNATURE, DECLINED, UNKNOWN_*, VALIDATION_FAILED) is the vendor working and counts nothing. `port` is the capability name and `provider` the bound registry name (`simulator`, `crowded`, `stripe`, ...). The signature of `resolve` is unchanged; without a sink it returns the bare port (tests compare it to a simulator). `apps/api/src/main.ts` and `apps/worker/src/main.ts` pass `stdoutMetrics`.
- No double count: `card-issuing.parseAuthorization` is skipped by the wrapper because `JitService.handle` already emits `provider.error{port: card-issuing}` for it (T-0053); that emission is untouched.
- `provider.error` keeps the alarmed dimension set `{port}` and, when a provider is given, adds `{port, provider}` as a second dimension set on the same EMF line (`optional` in `METRIC_DEFS`), so the existing alarms read the same series and no Terraform changes. `provider` and `reason` join the closed dimension set.
- `webhook.rejected{provider,reason}` (Count) is emitted in `InboundEventStore.record` for every delivery whose signature failed, which covers `WebhookRouter` and `/webhooks/crowded`; each passes the verifier's reason, mapped by `webhookRejectReason` to `missing_signature | bad_signature | stale | other`. The event id, payload and verifier text never become a label. No alarm (out of scope).
- A forged delivery the verifier cannot give an event id (bank credit with no `eventId`, malformed JSON) is refused with VALIDATION_FAILED before it can be recorded; `WebhookRouter` counts it through `InboundEventStore.countRejected` first, so each rejected delivery counts exactly once and an ok delivery never does.
- Owner note before deploy: the existing `us_banking_errors` alarm on `provider.error{port=institution-banking}` (5 or more in 5 minutes, pages) receives data for the first time with this card.
- By design, coded port errors other than PROVIDER_UNAVAILABLE (BAD_SIGNATURE, DECLINED, UNKNOWN_*, VALIDATION_FAILED, ...) are not counted.
- Not done: `var.provider_ports` in `infra/terraform/modules/alarms` still lists only `card-issuing`, so the new series for other ports have no per-port alarm or dashboard line yet; adding ports there adds alarms and is for a later card with an owner decision.
