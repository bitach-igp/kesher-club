# T-0036 [SETUP] The mobile layout tests warm their module graph, so CI's first test does not time out
REQ: REQ-AUTH-001 (enabling; found by CI on T-0617) · Sprint: 12
Files: apps/mobile/app/_layout.test.tsx, specs/tasks/T-0036.md, specs/tasks/README.md
Test first: `apps/mobile/app/_layout.test.tsx` as it stands, on a loaded runner.

**What failed.** CI's "lint · typecheck · unit · trace" job went red on T-0617's PR: `@kesher/mobile#test`,
`app/_layout.test.tsx` > "signed out, it routes to (auth)/sign-in; signed in, to (tabs)/home", *Test timed out in
5000ms* (5,044 ms). Lint and typecheck passed; the job carries all four names.

**Why.** Each test calls `vi.resetModules()` and imports `_layout.tsx`, which pulls in react-native-web and every
screen the layout reaches. The first import transforms that whole graph: about 1,000 ms locally, and about 5,000 ms
on a runner that is also running eleven other packages' suites. Later imports come from the transform cache in tens
of milliseconds. The cost was charged to whichever test came first.

**Change.**
- A `beforeAll` with its own 60-second budget imports the layout once, so the transform happens before any test's
  clock starts.
- Every test still imports a fresh module per build environment.
- No test's timeout was raised.

**Evidence.**
- Locally, the first test drops from 1,021 ms to 48 ms.
- In the same CI log, no other test runs within 2 s of its limit.
