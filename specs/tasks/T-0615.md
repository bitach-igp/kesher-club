As built:
- The data port grew `listInstitutions`, `getInstitution(id, by)`, `recordDeposit` and `decideDeposit`, with an `INVALID` code for the API's 422. `by` on `getInstitution` decides `recordedByMe` in the seeded binding; the HTTP binding reads it from the API, which reads the token.
- The decision route nests under the institution (`/institutions/{id}/deposits/{depositId}/{decision}`) so its redirect lands back on the page it came from. Refusals come back as `?error=<code>` or `?problem=<fields>` and the page renders words, never a problem body.
- The record form carries a fresh uuid as its Idempotency-Key, so a double submit records once.
- The list shows name, market, active staff and onboarding date; balances are on the institution's page. The admin list endpoint carries no balances, and a read per row is not worth it at pilot size. Add `balances` to `AdminInstitution` when the list grows.
- A second finance persona, Fern Finance (`staff-finance-2`), joins the simulator's sign-in so the two-person rule can be walked locally.
- With `institutions.deposits` off, the page still shows staff and says there is nothing to record.
