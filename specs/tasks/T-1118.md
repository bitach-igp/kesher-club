REQ: REQ-AUTH-008 (SECURITY: independent reviewer required, the author must not review it) · Sprint: later · dark/before `auth.orgSso` is turned on
Files (after the decision): apps/api/src/main.ts, apps/worker/src/main.ts, apps/api/src/config.ts and its test (the new key and validation), apps/api/src/main.test.ts, apps/worker/src/main.test.ts, docs/setup/secrets.md only if the source is a secret, specs/tasks/T-1118.md, specs/tasks/README.md. `apps/api/src/app.ts` (shared composition root) only if the agreement check cannot live in `main.ts`; say so in the PR.
Source: T-0790 and T-0791 are built and inert. `AppOptions.orgIdp.orgs` (institution to directory id and SCIM bearer) and `staffAlertEmail` are read by the webhook and the sweep, but neither `main.ts` passes them, so a deployed API knows no directory: every delivery is a recorded no-op and the sweep finds no institution. Turning `auth.orgSso` on today changes nothing and looks like it works.
Decisions (owner or ops, recorded on the card before code):
1. Config source. ADR-004 puts the per-institution record (WorkOS organisation id, directory id) in configuration. Which store: a per-market config file, a secret-store JSON, or a table? The SCIM bearer is a secret and never goes in a file in the repo.
2. Uniqueness. A directory (or WorkOS organisation) claimed by two institutions is a mis-keyed event that could deprovision at the wrong institution: the card default is that boot REFUSES (crash with the key names, never the values).
3. Two sources, one truth. The adapter holds `orgs` (WorkOS ids) and the app holds `AppOptions.orgIdp.orgs` (directory id and bearer): they are built from one record by one function. A boot-time agreement check compares the two; divergence refuses to boot (card default) or, if the owner prefers, boots with the feature off and pages. Say which.
4. `staffAlertEmail`: which mailbox, per market or global.
Behaviour (card defaults): `main.ts` of the API and of the worker build `orgIdp.orgs` and `staffAlertEmail` from the chosen source with Zod validation; an institution with no record is simply absent (inert for it); the worker's sweep and the API's webhook read the SAME built record.
Test first: TST-AUTH-008: (1) a config with one institution yields a webhook that deprovisions and a sweep that lists it; (2) two institutions claiming one directory id (or one WorkOS organisation id) refuse to boot, naming the keys not the values; (3) a divergence between the adapter's `orgs` and `orgIdp.orgs` follows the decision (refuse or off-and-page); (4) no config means exactly today's behaviour; (5) no secret appears in a boot log or error.
Done when: listed tests pass; `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm trace` green; only listed files touched. About 250 lines.
