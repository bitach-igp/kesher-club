  `handoff/desktop/T-0310-membership-cancel-at.md`. The vendor's cancel answer carries the date (the subscription's

- **`GET /memberships`** lists the caller's memberships as funder (with the member's display name) and as member,
  newest first, none still being set up.
- **`POST /memberships/{id}/cancel`** (Idempotency-Key, `HEADER_OPS`): the funder only (the member 403, anyone else
  404). `BillingPort.cancel(…, 'period_end')`; the membership stays `active` with `cancelAt` until the vendor ends it.
  A second cancel, with any key, returns the same date; an ended membership answers 409, and the vendor's own
  "already ended" maps to 409 too. Nothing touches the member's purses.
