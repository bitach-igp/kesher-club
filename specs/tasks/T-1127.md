# T-1127 [AUTH] Durable auth-event outbox and a consumer, so `new_device_sign_in` reaches the member (security, independent reviewer; probably a migration and a desktop apply request, SCOPE ONLY)
STATUS: open (scoped 2026-11-27 from the #425 review). SCOPE ONLY: a plan; the migration and the handoff request are written when the card is built. Gates `auth.orgSso`.
REQ: REQ-AUTH-008 (SECURITY: independent reviewer required, the author must not review it) · Sprint: later · dark/before `auth.orgSso` is turned on
Files: apps/api/src/auth/passkeys.ts (the `events` sink), the SSO, social and passkey emit sites, a new consumer, db/migrations/ops/<next number>_auth_event_outbox.sql with atlas.sum and a handoff request in handoff/desktop/ (per `handoff/README.md`), specs/tasks/T-1127.md, specs/tasks/README.md
Source: The independent review of #425 (T-1121): `new_device_sign_in` and the other auth events go to `PasskeyService.events`, a plain in-memory array that is never drained. No member receives a new-device alert for passkey, social or SSO sign-in today, and the events are lost on restart. T-1121 made SSO emit the event; this card makes any sign-in method's event reach someone.
Shape: an insert-only outbox table written in the same transaction as the device row where the store allows it, and a worker consumer that delivers the alert through the messaging port, with retry and an idempotency key per event. The event body stays free of IdP claims.
Also pinned here: the sink-throws-after-device-write alert-loss case (mutant M29, `DELIVERED_AFTER_RETRY = 0` in `apps/api/src/institutions/staff-sso.test.ts`). Flip that constant to 1 when the outbox lands: a sink failure after the device write must still deliver once, after a retry.
Test first: an event emitted by each of the three sign-in methods is delivered once; a restart between emit and delivery loses nothing; the M29 pin reads 1.
Out of scope: the content and channel of the alert copy (a messaging card).
Done when: the listed tests pass; `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm trace` green (plus `pnpm db:lint` when a migration changed); only listed files touched.
