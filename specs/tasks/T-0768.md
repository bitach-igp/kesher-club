Design: `ops.workflow_marker (kind text not null, subject_id uuid not null, seq integer not null default 0, value text not null, created_at timestamptz not null default now(), primary key (kind, subject_id, seq))`, plus `unique (kind, value)` for the lost-key lookup by value, grants `select, insert` to `club_app` (markers are write-once; `on conflict do nothing`), `check (seq >= 0)`. No provider column: markers are keyed by the entity they describe, which is a transfer or party id, so a provider change cannot collide. `workflow-marker.ts` exports `putMarker(db, { kind, subjectId, seq?, value }): Promise<boolean>`, `getMarker`, `getMarkers(db, kind, subjectId, seqs)`, `findByValue(db, kind, value)`, nothing else; T-0769 and T-0770 are its only callers. `db/lint.mjs` house rules (header naming the task, timestamptz, no update or delete grants on ledger tables) apply.
