# T-0052 [SETUP] Structured logging with redaction and a request id

Test first: the apps write ad-hoc `console` lines (`review/CODEBASE-REVIEW.md` found no logger). Add one JSON logger: level, time, service, market, request id, route, status, duration; a request id comes from the load balancer header or is minted and returned in `X-Request-Id`. Redaction by construction: the logger accepts a fixed set of fields, not arbitrary objects, and a test feeds PAN-, CVV-, OTP-, token- and e-mail-shaped values through every field and asserts none appears in the output (constitution: never log PAN, CVV, OTPs, tokens or PII). Errors log class and code only (as the worker already does). Replace the `console` calls in `apps/api/src/main.ts` and `apps/worker`.
Done when: listed tests pass; `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm trace` green; CI's terraform job green when `infra/` changed; only listed files touched
Out of scope: tracing; shipping logs anywhere beyond CloudWatch (the log groups already exist, with a CMK). Stop and ask on conflict with the spec.
As built:
- `createLogger` in `@kesher/domain` (`packages/domain/src/log.ts`): one JSON line with `at`, `level`, `service`, `market` and `event`. It takes a closed list of fields (numbers: `status`, `durationMs`, `ms`, `port`, `drainMs`, `jobs`; text: `market`, `route`, `method`, `job`, `error`, `code`, `message`, `signal`, `mode`; ids: `requestId`, `traceId`; the `providers` map). A field outside the list is dropped and only its name is recorded in `dropped`. Text is scrubbed of JWTs, bearer tokens, e-mail addresses, card-number runs, long hex or base64 runs and any 4 to 8 digit number (an OTP cannot be told from another number, so numbers belong in the numeric fields). Ids must match `^[A-Za-z0-9-]{8,64}$` or print `[invalid]`.
- API: `createServer(app, log)` writes one `request` line per response (request id, method, the contract's operationId or `mcp` or `unmatched`, status, duration) and never the URL, query, headers or body. `x-request-id` from the load balancer is kept when well formed, else a UUID; it is returned in `X-Request-Id` and becomes the problem body's `traceId` when there is no `traceparent`. `main` logs with its market once the config is loaded; the exported `log` covers boot failures and signals.
- Worker: the scheduler's flat `Log` type is unchanged; its sink is the shared logger, so every worker line now carries `level` and goes through the same scrubbing.
- The request-id header is not yet an AWS trace id: the ALB sets `x-amzn-trace-id`, not `x-request-id`. Correlating with ALB access logs is a later change if wanted.
- Not done: tracing; shipping logs beyond CloudWatch.
