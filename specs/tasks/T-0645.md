## As built
- **Two endpoints** with the same reader and the same access rule:
  - `GET /institutions/{id}/statement?month=&currency=` returns JSON (`InstitutionStatement`).
  - `GET /institutions/{id}/statement/export?…&format=csv|xlsx` returns the base64 envelope. The download is split
    out as collections splits its export, so one operation never answers two shapes.
- **Access.** Finance staff and admins of the institution; other staff get 403, another institution 404.
- **What it covers.** The institution's own account in that currency (T-0613):
  - The opening balance is every posting before the month.
  - Each row is one journal that posted to the account in the month, with the running balance after it.
  - The closing balance is the opening plus the rows, so it reconciles by construction.
  - The shared pre-T-0613 master account and the ACH hold account are not the institution's balance and are not
    shown.
- **Rows.** Amounts are from the institution's side: money in positive, out negative. The description is the
  journal's own text when it has one, else the kind in words.
- **Files.**
  - CSV and XLSX carry the same cells: an opening line, the rows, and a closing line whose amount is the month's
    net.
  - The CSV neutralises a description that starts like a formula.
  - `export.ts` gains `xlsx(sheetName, rows)`, extracted from `toXlsx`, which now calls it. The collections export
    is unchanged and its tests pass.
