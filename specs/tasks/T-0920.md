Test first: the REC files in `handoff/done/recordings/` show each flow's automated tests, not the product (docs/bank-review/README.md, "Recordings"). This card scripts each flow against the T-0031 stack with the T-0032 personas, in Playwright with `recordVideo`. The browser records its own pages, so no screen capture is needed and nothing outside the page is in the video. It runs in CI or in a cloud session. Each video has three panes: the member app (T-0033) where a screen exists, the simulator panel for the vendor's side (and the clock for holds), and the console's Customer 360 (T-0919) for the booked result. Where no member screen exists, the step is an `@kesher/sdk` call printed as a caption ("API: POST /wallet/loads"), never presented as a screen. Coverage by flow: REC-01, 02, 03, 04 (loads, ACH hold and release, other purse, auto-reload): no add-money screen, so SDK call, then wallet balance and activity in the app; REC-05, 07, 08 (send, cross-currency, requests and splits): the pay screens; REC-06 (new-pair hold): pay screens, then the clock advance and release; REC-09 (assistant-proposed send): the intent created through the SDK, approval through the API with a simulator passkey (no approval screen yet). Each spec asserts the amounts on screen and in Customer 360 equal the `money-flows.md` worked example (bigint, minor units), so a recording cannot pass while showing a wrong number.
