Test first: TST-INS-011 (checks rows). The port (use the `club-adapter` skill) has three calls:
- `lookupEntity({ market, identifier, name })`: registry status, name match, entity type;
- `exemptStatus({ market, identifier })`: ניהול תקין year, or Pub 78 / master-file presence, auto-revocation, and a possible-church flag;
- `screen({ names[] })`: potential matches with list, score and reference.

The simulator's fixtures are deterministic:
- an amuta number ending 000 is struck off;
- an EIN absent from its table is a possible church;
- a name containing "Sanctioned" is a potential match.

`KybChecks.run(institutionId)` calls the port and writes one check row per result, with the provider and the evidence reference. It never stores a document or an image. The contract suite runs against the simulator now and against a vendor later. Vendor bindings stay behind `institutions.kyb.checks` (default false) until the bank answers the questions in `docs/bank-review/institution-kyb.md`.
Done when: listed tests pass; the contract suite runs green on the simulator; `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm trace` green; only listed files touched
Out of scope: any real vendor adapter (one card per vendor, once chosen). Stop and ask on conflict with the spec.

As built:
- `KybPort` is the 19th port. It is in the catalogue, in the live spec's port table (Tab 3 §4), in the simulator host with its fixtures on the panel, and in the admin bindings list. That is why the catalogue and bindings tests now count 19. The card's `packages/simulators/src/registry.ts` is `apps/simulators/src/host.ts` in this repo.
- The port is read-only (`lookupEntity`, `exemptStatus`, `screen`). The same question gets the same answer, so it takes no idempotency key. Only the names sent come back; the contract asserts that no date of birth, address or identity number does.
- `POST /admin/institutions/{id}/kyb/run` (compliance) takes the identifier (amuta or company number, or EIN) and the legal name. The card did not list an endpoint, but T-0926's "Run checks" needs one.
- The run makes every port call before it writes, so an outage records nothing. Each check row carries the provider and its reference. The identifier row keeps `registeredName`, which the own-name payout check (T-0623) reads. A malformed identifier answers 422, and an outage 503.
- The run refuses with FEATURE_OFF while `institutions.kyb.checks` is off, even though the simulator would answer. A simulator's "clear" must never become evidence in production. Development turns every flag on, so the demo can run it.
