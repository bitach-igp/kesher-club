# T-0022 [SETUP] The worker runs every sweep on its cycle
REQ: — (enabling; ADR-002 "the plain scheduler until then"; after T-0020) · Sprint: 9
Files: apps/worker/src/scheduler.ts, apps/worker/src/scheduler.test.ts, apps/worker/src/lock.ts, apps/worker/src/lock.test.ts, apps/worker/src/jobs.ts, apps/worker/src/jobs.test.ts, apps/worker/src/index.ts, apps/worker/src/main.ts, apps/worker/src/main.test.ts, apps/worker/package.json, pnpm-lock.yaml, apps/worker/Dockerfile, apps/worker/README.md, apps/api/src/pg.ts, apps/api/src/pg.test.ts, handoff/desktop/T-0022-docker-build.md
Test first: the scheduler, on a fake clock: every job runs on its cycle from boot; a run longer than its cycle is never overlapped (the next run starts after it ends); a job that throws logs one line (job name, error name and code; no payload, member data or token) and runs again next cycle while the other jobs carry on; SIGTERM lets in-flight runs finish and stops scheduling. One runner per job across worker tasks: each run holds a session-level `pg_try_advisory_lock` on a 64-bit hash of the worker's market and the job name (so the IL worker never makes the US one skip), on a one-connection pool of its own that never reaps an idle connection (`createPgDatabase`'s new `idleTimeoutMs: 0`), and gives it back when the run ends, so a second task skips the run instead of doubling it. (A transaction-scoped lock per run would pin one pool connection per running job while that job's own queries wait for another: fourteen jobs at boot on a pool of ten deadlock.) The job table (`jobs.ts`) registers each job below with its declared cycle constant; `jobs.test.ts` lists `apps/worker/src/**` and fails on any module exporting a job class, a `sweep` or a `run` that is neither in the table nor named in its exclusion list with a reason, so the next job cannot be forgotten. `main(env)` against PGlite behind the socket server builds the services through `createApp` (the worker never serves HTTP), runs one cycle of every job, and exits cleanly on SIGTERM. The Dockerfile builds the image the preview workflow expects at `apps/worker/Dockerfile`, as a non-root user
