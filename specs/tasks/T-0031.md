# T-0031 [SETUP] One local process runs the API, the jobs and the simulator panel on one registry and one clock
REQ: — (enabling; bank-review recordings, after T-0021, T-0022 and T-0912) · Sprint: 10
Files: apps/worker/src/dev.ts, apps/worker/src/dev.test.ts, apps/worker/package.json, apps/demo/compose.yaml, docs/setup/demo.md, specs/tasks/T-0031.md, specs/tasks/README.md
Test first: today the API (`apps/api/src/main.ts`) and the worker (`apps/worker/src/main.ts`) each call `createRegistry` and get their own simulators, and the simulator host (`apps/simulators`) starts a third set. A load the API submits is unknown to the worker's sweep, and a hook run on the panel changes neither process, so no flow can be driven end to end on a running stack. `dev.ts` builds one `createRegistry('sim')` with one advanceable clock and passes it to three things: the API server (`createServer(createApp(…))` on `PORT`), the job scheduler (`buildJobs`, same deps as `main.ts`), and the simulator panel (`createServer(simulators)` from `@kesher/simulators` on `SIMULATOR_PORT`). It boots only when `APP_ENV` is `development`, and otherwise exits 1 with one `boot_failed` line, like `main.ts`. When `JWT_SIGNING_KEY`, `STAFF_JWKS`, `PII_DATA_KEY` and `PII_INDEX_KEY` are unset it generates throwaway keys at start, holds them only in memory and never prints them. `dev.test.ts` runs on PGlite through `createTestDatabase()`: (1) `APP_ENV=preview` exits 1; (2) an ACH load posted to the API answers `pending_hold`, `POST /clock/advance` on the panel moves the shared clock past the release date, the next `ach-release-holds` job run settles it, and the member's balance read through the API shows the money (bigint); (3) a hook on the panel (`billing/failInvoice`) is seen by the API's next call. `pnpm --filter @kesher/worker dev` starts it; `apps/demo/compose.yaml` runs Postgres 16 on 5433 for it.
Done when: listed tests pass; `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm trace` green; `docs/setup/demo.md` gives the three commands (compose up, migrate, `pnpm --filter @kesher/worker dev`) and the two URLs; only listed files touched
Out of scope: seed data (T-0032), the member app (T-0033), staff sign-in (T-0919), any change to `main.ts` or the deployed images. Stop and ask on conflict with the spec.
