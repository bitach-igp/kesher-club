# T-0031 [SETUP] One local process runs the API, the jobs and the simulator panel on one registry and one clock
REQ: — (enabling; bank-review recordings, after T-0021, T-0022 and T-0912) · Sprint: 10
Files: apps/worker/package.json, apps/demo/package.json, apps/demo/tsconfig.json, apps/demo/src/dev.ts, apps/demo/src/dev.test.ts, apps/demo/compose.yaml, pnpm-lock.yaml, docs/setup/demo.md, specs/tasks/T-0031.md, specs/tasks/README.md
Test first: today the API (`apps/api/src/main.ts`) and the worker (`apps/worker/src/main.ts`) each call `createRegistry` and get their own simulators, and the simulator host (`apps/simulators`) starts a third set. A load the API submits is unknown to the worker's sweep, and a hook run on the panel changes neither process, so no flow can be driven end to end on a running stack. `dev.ts` builds one `createRegistry('sim')` with one advanceable clock and passes it to three things: the API server (`createServer(createApp(…))` on `PORT`), the job scheduler (`buildJobs`, same deps as `main.ts`), and the simulator panel (`createServer(simulators)` from `@kesher/simulators` on `SIMULATOR_PORT`). It boots only when `APP_ENV` is `development`, and otherwise exits 1 with one `boot_failed` line, like `main.ts`. When `JWT_SIGNING_KEY`, `STAFF_JWKS`, `PII_DATA_KEY` and `PII_INDEX_KEY` are unset it generates throwaway keys at start, holds them only in memory and never prints them. Every flag in `config/flags.json` is on in this process, in memory only (the flag table is untouched), because the demo exists to show the gated flows. `dev.test.ts` runs on PGlite through `createTestDatabase()`: (1) `APP_ENV=preview` exits 1; (2) an ACH load posted to the API answers `on_hold` (its transfer `pending_hold`); the panel's `funding/settle` hook signs the vendor's confirmation for that very load (a separate simulator host has never heard of it) and the API accepts it; `ach-release-holds` leaves it held until `POST /clock/advance` on the panel moves the shared clock past the release date, then settles it; the API's own clock has moved too (the 10-minute access token has expired and is refreshed), and the member's balance read through the API shows the money (bigint). `pnpm --filter @kesher/demo dev` starts it (`apps/demo` is the demo's own package: it imports `@kesher/api`, `@kesher/worker` and `@kesher/simulators` and is never built into an image; `apps/worker/package.json` gains `exports` like `@kesher/api`'s so `buildJobs` and `pgRunLog` can be imported); `apps/demo/compose.yaml` runs Postgres 16 on 5433 for it.
