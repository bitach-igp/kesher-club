Test first: TST-AGT-006. An assistant's money tool creates a pending intent, and the member approves it with `POST /intents/{id}/approve`. But no endpoint lets the app show what is being approved. Add `GET /intents?state=pending` and `GET /intents/{id}`, for the member's own intents only. Each returns the kind (send, load), the amount, the recipient's display name, the assistant's client name, the time created and the expiry. Anything the assistant wrote travels as untrusted text and is labelled so (REQ-AGT-007 wrapping). Add `POST /intents/{id}/decline`. The tests cover: another member's intent is 404; an expired intent lists as `expired` and cannot be approved; the agent's own token cannot call these, and `apps/api/src/mcp/tools/registry.ts` wraps none of them (member scope only, never an MCP tool).

As built:
- **Operations.** `GET /intents` (optional `state`), `GET /intents/{id}` and `POST /intents/{id}/decline` (Idempotency-Key, no step-up) answer a `MemberIntent`:
  - `kind` is send, load, card_purchase or limit_change, mapped from the stored kinds and the agent-purchase action.
  - `status` is as of now, so a pending intent past its 24 h reads `expired`, swept or not.
  - It also carries the amount; for sends, the recipient's party id and masked phone (`•••• 0101`); the assistant's grant and client id; and `createdAt`, `expiresAt` and `decidedAt`.
  - Display text sits in `untrusted`: the client's registered name, the assistant's note, a roster name for the recipient, and the processor's merchant name.
  - The table has no `created_at` column, so `createdAt` is `expiresAt` minus the 24 h TTL; no migration was needed.
- **No server-side names.** No member display names exist on the server, since sign-up collects none. The recipient is a masked phone, plus a roster name when an institution has one. The app adds the name from the phone's contacts.
- **Declining an expired intent.** It now marks the intent expired and answers IDEMPOTENCY_CONFLICT, as approval already did. Before this, a stale intent could be declined.
- **Shared plumbing.** `apps/api/src/app.ts` gains the three handlers. The IntentService gets the identity store as an optional last constructor argument (`PeopleLookup`), used only to mask the recipient's phone.
- **Agent tokens.** An assistant's token is refused with 401. The test signs one with the API's own key, so only its MCP audience differs. `TOOLS` wraps none of the four intent operations.
