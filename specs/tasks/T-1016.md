# T-1016 [AGT] Authorization server, part 3: the token endpoint, with PKCE and rotating refresh tokens
REQ: REQ-AGT-011, REQ-AGT-002 (after T-1015) · Sprint: 13
Files: apps/api/src/oauth/token.ts, apps/api/src/oauth/token.test.ts, apps/api/src/server.ts, apps/api/src/app.ts, apps/api/src/agent/grants.ts, contracts/openapi.yaml, packages/sdk/src/schema.generated.ts, specs/tasks/T-1016.md, specs/tasks/README.md; shared plumbing: apps/api/src/routes.ts
Test first: TST-AGT-011. `POST /oauth/token` takes `application/x-www-form-urlencoded`, as OAuth requires; `server.ts` parses that content type alongside JSON. Behind `mcp.enabled`:
- `authorization_code`:
  - checks the code once, within 60 seconds, against the client, redirect URI and `code_verifier` (S256);
  - answers an access token (ES256, 10 minutes, `aud` set to the MCP URL, `sub`, `scope`, `grant_id`, `client_id`, `jti`) and a refresh token (opaque, hashed, 30 days).
- `refresh_token`: rotates; the old one stops working. Presenting an already-rotated one revokes the grant.
- Revoking a grant (T-1006) ends its refresh tokens.

The tests cover:
- a wrong verifier, a reused code and an expired code answer `invalid_grant`;
- the access token passes `McpTokenValidator` and is refused by the member API (and a member token by /mcp);
- refresh rotates;
- a replayed refresh token revokes the grant, and the next /mcp call is 401;
- a revoked grant's refresh answers `invalid_grant`.

Out of scope: token introspection and revocation endpoints (the grants screen revokes). Stop and ask on conflict with ADR-009.
