Out of scope: processor-side latency (ADR-006 vendor). Stop and ask on conflict with the spec.

As built:
- `tools/loadtest/jit.js` (k6): two `constant-arrival-rate` scenarios, `steady` (`LOAD_RPS`, default 50, for `LOAD_DURATION`, about 10 % declines: half unknown card, half an amount no wallet holds) and `burst` (`BURST_SIZE` parallel authorisations for one wallet every second, the T-0544 lock path). Thresholds `http_req_duration p(99)<300` and `http_req_failed rate<0.01`. Counters `jit_approved`, `jit_declined`, `jit_unexpected`. `lib.mjs` holds the shared pure code (prod guard, signing headers, request builder, decline mix); `guard.mjs` is the workflow's guard; `seed.mjs` has `manifest` (seed-query rows to `cards.json`, bigint balances) and `check` (one decline-only probe); `lib.test.mjs` is the node test.
- Signing: the card simulator checks the constant header `x-sim-signature: sim` and there is no HMAC, so k6 needs no crypto. The value is read from `JIT_SIGNATURE` (secret `STAGING_JIT_SIGNATURE` in the workflow), never written in the script. The test runs the built requests through the real `CardIssuingSimulator.parseAuthorization`.
- Prod guard: `assertNotProd` refuses a host with a prod label, a host that does not name staging/preview/sandbox/dev/localhost, credentials, plain http outside localhost and any path but the JIT route; it runs in the k6 init context, in `seed.mjs check` and as the workflow's first step. `.github/workflows/loadtest.yml`: `workflow_dispatch` plus a nightly cron, `contents: read`, target from the variable `STAGING_JIT_URL` (the job is skipped while it is empty), cards from `STAGING_LOADTEST_CARDS`, k6 by `grafana/setup-k6-action@v1` at 1.3.0, summary in the job summary and as an artifact.
- Tests: `tools/loadtest/lib.test.mjs` (guard accept and refuse lists, signing against the simulator, request shape equal to `authorize()`, the decline mix, the seed manifest). Run by the root `pnpm test`: `package.json`'s `node --test` list gained `tools/loadtest/*.test.mjs`.
- Deviations: (1) Seeding through the public API is not possible: sign-in needs a passkey ceremony, a load needs a fresh step-up and no endpoint returns the processor card id the JIT call uses. `seed.mjs` turns the rows of a read-only staging query into the manifest, and the README documents the member, KYC-webhook and load steps. (2) "Record the first result in docs/ops/" is NOT done: staging is not deployed and the session had no k6 or network. `docs/ops/jit-load-test.md` holds the exact command and a pending row; no number was invented. (3) Extra files beyond the card's list: `docs/ops/jit-load-test.md`, `package.json` (test glob), `.gitignore` (`tools/loadtest/cards.json`). (4) The test imports the simulator by relative path (`packages/ports/src/card-issuing.simulator.ts`): `@kesher/simulators` does not resolve from the repository root, and `CardIssuingSimulator` lives in `@kesher/ports` anyway. (5) The k6 script itself has not been executed here (no k6); the pure parts are tested in node. The workflow's variable names, k6 version and the nightly slot are unverified until staging exists.
