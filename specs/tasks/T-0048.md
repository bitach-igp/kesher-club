## As-built
- Files beyond the list: `pnpm-lock.yaml`, `apps/web/{.gitignore,tsconfig.json,vitest.config.ts,README.md,public/lang.js}`. Terraform: only `web_bucket_name` and `web_distribution_id` outputs added to `envs/{staging,prod}/main.tf` (outputs.tf is not in Files, as earlier cards did).
- Legal URL shape: one page per docKey at `/legal/<docKey>` with both languages in the HTML; `?lang=` is read client-side by `/lang.js`. Matches `apps/mobile/src/consent.ts`. The deploy also uploads each page under its extensionless key.
- Well-known files are one route handler (`app/.well-known/[file]/route.ts`) that writes them into `out/` at build; the Stripe file only when `STRIPE_APPLE_PAY_DOMAIN_FILE` is set.
- PLACEHOLDERS T-0058 must set: `iosBundleId`, `appleTeamId`, `androidPackage`, `androidCertSha256` in `apps/web/src/app-ids.ts` (`apps/mobile/app.json` has none yet); `SUPPORT_EMAIL` in `apps/web/src/site-config.ts` (owner decision); the Stripe file (issued per domain). Staging and production builds fail until they are real.
- Decisions: `staging` is as strict as `production` for ids and support address (T-0059 tests passkeys on staging); only production requires the Stripe file. AASA excludes `/`, `/support`, `/legal*` from applinks so the app's legal links open in the browser.
- Not verified: no AWS (workflow, content types, invalidation, the distribution-origin guard's domain format untested), no build against the real legal API (a fixture HTTP server stands in), no real device passkey/universal link. The CDN CSP blocks Next's inline bootstrap scripts (harmless, documented in the README).
- Tests: `pnpm --filter @kesher/web test` builds the real site four to six times (about 30 s).
- Review round 1: (a) the web bucket is SSE-KMS with `module.kms_s3`, whose key policy granted CloudFront nothing, so every OAC read would be denied. `modules/kms` gained an optional `cloudfront_distribution_arns` (default empty, backwards compatible) that adds a `cloudfront.amazonaws.com` statement for `kms:Decrypt` and `kms:GenerateDataKey*` conditioned on `AWS:SourceArn`; both env roots pass `[module.web.distribution_arn]` (new output of `modules/cloudfront-waf`). No cycle (validate passes): the distribution depends on the bucket, not on its encryption configuration. `tests/kms.tftest.hcl` covers it. Not applied to AWS. (b) `turbo.json` declares `WEB_ENV`, `LEGAL_API_URL`, `STRIPE_APPLE_PAY_DOMAIN_FILE`, `WEB_DIST_DIR` and `out/**` for `@kesher/web#build`; verified with `turbo run build --filter=@kesher/web`. (c) Dates are shown in Israel time. (d) The legal pages are frozen at build: redeploy after publishing a version and on the day a future-dated one takes effect (no cron: prod needs reviewer approval). (e) Deploy script: no trailing newline in the Stripe file, and a failing `find` aborts the upload. (f) Legal pages have a per-document `<title>`. Notes left as is: the CSP blocks Next's inline scripts; the AASA `applinks` claims all paths except the marketing ones until T-0058 defines deep links; each language block has its own `<h1>`.
