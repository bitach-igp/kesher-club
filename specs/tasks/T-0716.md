# T-0716 [LED] PostgresLedger takes two optional in-transaction hooks: before a journal posts and after it is inserted
REQ: REQ-LED-001, REQ-LED-003 · Sprint: later (ADR-018 decision of 2026-11-11, proposed)
Files: apps/api/src/ledger/post.ts, apps/api/src/ledger/post.test.ts, specs/tasks/T-0716.md, specs/tasks/README.md
Source: ADR-018, "Decision, 2026-11-11", M1 and M7. A mirror leg must commit with its journal or not at all (a crash between two transactions would lose it), and an exposure cap must refuse a journal before it is written. `PostgresLedger.write` already has the transaction and the `guard` seam (`apps/api/src/ledger/post.ts`, `write`, `postNoOverdraft`); neither hook exists. Today `ledger.post()` enqueues nothing (the outbox rows come from transfer state changes, not journals).
Assumption: M1 (a dedicated queue written in the journal's own transaction), M7 (a refusal before the write, fail closed). Design B only: under Design A (D1) this card is not needed.
Test first: TST-LED-001, TST-LED-003. `new PostgresLedger(db, { beforePost, onPosted })`: `beforePost(tx, input)` runs inside the posting transaction after the idempotency replay check and after the wallet locks of `postNoOverdraft`, before any insert; a throw from it writes nothing and the error reaches the caller unchanged (a `DomainError` keeps its code); `onPosted(tx, journal)` runs in the same transaction after the postings and the balance rows are written, with the journal's id, kind, key, postings and metadata; a throw from it rolls the whole journal back (no journal, no balance change); a replay of the same key returns the first journal and calls NEITHER hook again (the hook never runs twice for one journal); a journal that loses the unique-key race calls `onPosted` zero times for the loser; `reverse()` goes through the hooks like any journal; with no hooks given every existing test passes unchanged; `UNBALANCED` is still refused before either hook runs.
- Both options are optional and default to nothing; the constructor's first argument is unchanged, so no caller changes. The hooks are for the composition root (T-0721 wires them), never for a module.
Done when: listed tests pass; `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm trace` green; only listed files touched
Out of scope: what the hooks do (T-0717, T-0721, T-0724); the app wiring; a migration; any change to a journal's shape.
