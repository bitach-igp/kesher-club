Test first: TST-ADM-001 (Customer 360 rows). Found while recording REC-01 to REC-05 (T-0920): Customer 360 showed KYC "none" and no cards for every member. The read model hardcoded both "until the card programme lands" (E04), and E04 landed. KYC now comes from `identity.kyc_session`, read the way `KycService.status` reads it: verified at the highest approved tier, else the latest session's state (review reads as pending), `none` before any session. Cards come from `cards.card`, newest first, with active wallet tokens counted; nothing past the last four digits leaves. The console's balances also subtracted holds from an `available` that already excludes them, so a $100 ACH hold showed $100 less "spendable" than the member could spend. The columns are now Available (the member's own number), Holds, and Total (available + holds). The tests cover: none → rejected → verified T1, where a later pending T2 does not hide the approval; cards in order with only active tokens counted and no processor id in the document; $80 available with $20 held reads Total $100.
Done when: listed tests pass; Spectral clean; `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm trace` green; only listed files touched
Out of scope: KYC documents or images (never stored), card controls and transactions in Customer 360. Stop and ask on conflict with the spec.
