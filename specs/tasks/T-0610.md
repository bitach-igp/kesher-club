As built:
- **The API now enforces step-up on a run.** `runAllowance` took no step-up, so "Run takes a step-up" would have been console theatre. A run with `dryRun: false` now needs `X-Step-Up` younger than 5 minutes (REQ-AUTH-006). That includes the second finance member's Approve, which posts the same run. A preview needs no step-up. HEADER_OPS marks the operation `stepUp: true`, and the console sends an empty header for previews. The API tests sign the finance users up with passkeys and check three cases: no token, another person's token, and a fresh token.
- **Preview rows.** The preview gains `rows` (roster name and amount), so the screen can show "members, amounts, total". The model refuses to show a preview whose rows do not add up to its total (bigint).
- **The requester never sees Approve.** Run history gains `requestedByMe`, so the console can hide Approve without seeing anyone's party id.
- **A bug the browser run found.** Previewing a date that had already run turned that run back into `preview` (the activity upserted unconditionally). The history then read "Previewed" for a run that had paid, and the schedule's next date went back. A preview now never overwrites a real run; a regression test in `allowance-runs.test.ts` fails without the fix. Money was never at risk: each payment's key is the run and the member.
- **Step-up in the console.** The console relays the step-up through server actions into a 5-minute httpOnly cookie, which the run action puts on `X-Step-Up`; page script never holds the token. A local demo console signs step-ups as the persona that signed in (sessionStorage, development builds only). The production build was checked again for persona code: none.
- **The proxy passes the resolved access token.** It sends it on a server-side request header, so a page or action in the same request uses the token it just refreshed.
- **Hebrew.** The copy is mirrored in Hebrew, and the browser's first language sets `lang` and `dir`. Staff display names come from the API in English ("Finance •••• 0109"); localising them is a later card.
- **Verified in Chromium**, against the seeded yeshiva plus a scratch harness that, inside its own PGlite only, activated three students and added two schedules (no endpoint creates them yet):
