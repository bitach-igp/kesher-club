# T-1125 [AUTH] Purge or TTL for the SSO marker rows, and a PII-free log line when `callback()` swallows an internal error (OWNER DECISION first; security, independent reviewer)
STATUS: open, needs a decision (scoped 2026-11-26 from the #422 review). The decision is what to build; then code.
REQ: REQ-AUTH-008 (SECURITY: independent reviewer required, the author must not review it) · Sprint: later · dark/before `auth.orgSso` is turned on; cross-reference T-1119 (the drift sweep's audit index)
Files: decided by the choice: apps/api/src/institutions/staff-sso.ts and its test for the log line; for the purge either db/migrations/ops/<next number>_sso_marker_purge.sql with atlas.sum and a handoff request in handoff/desktop/ (per `handoff/README.md`), or a new TTL table and its store; specs/tasks/T-1125.md, specs/tasks/README.md
Source: the independent review of #422 (T-0792), non-blocking finding (e): the SSO state, exchange-code, attempt and link-start rows are all `ops.workflow_marker` rows. The table is insert-only and `club_app` can delete only failed-owner markers, so these rows are never removed and grow with every start, including attacker-driven ones at the public start (the edge rate rule bounds the rate, not the total).
Options to decide: (1) a narrow delete trigger or grant like T-0787 (delete allowed only for the SSO kinds and only once expired; a migration with a desktop apply); (2) a separate TTL table for SSO state with its own purge job, leaving the insert-only marker table alone; (3) keep the rows and only add an index and a retention note (cheapest, unbounded). Say which and why; whichever is chosen must keep the write-once used markers unforgeable (a purged used-marker must never let a still-valid code be redeemed again: purge only after expiry plus a margin).
Second part, not blocked on the decision: `callback()` swallows internal errors and records only the metric reason `internal`. Add one log line (error class and the state's institution id at most) with no PII: no subject, email, code, state, cookie, or IdP claim. A test pins that none of those appear in the logged line.
Test first: (1) the log line is emitted on an internal error and holds none of the forbidden values; (2) per the choice: expired SSO rows are removed and live ones, and the used markers of live codes, are not; a purged state cannot be replayed.
Done when: the decision is recorded in the card; the listed tests pass; `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm trace` and (migration) `pnpm db:lint` green; real Postgres apply PASS in `handoff/done/` if a migration; about 150 lines.
Out of scope: the audit index (T-1119); the other cards.
