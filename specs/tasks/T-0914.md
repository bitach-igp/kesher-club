Test first: `apps/admin/src/infra-contract.test.ts` reads staging's and prod's `module "admin"` and fails unless it passes every key the console requires in `api` mode. The keys come from the schema plus the `api`-mode list `config.ts` exports and uses. `ADMIN_API_SIGNING_KEY` and `ADMIN_OIDC_CLIENT_SECRET` arrive as ECS secrets, never as plain environment. `ADMIN_DATA` is `api`, and both API URLs end in `/v1`. Client VPN source-NATs a client to its network interface in the subnet it is associated with, so the VPN gets subnets of its own. `network.tftest.hcl` asserts one per AZ, apart from every other tier, with the endpoint associated with them and not with the app subnets. The console's `ADMIN_VPN_CIDRS` is exactly those subnets, so an ECS task in the app subnets fails the IP gate. Phishing-resistant SSO stays behind it (REQ-AUTH-009). `markets.tftest.hcl` still plans both roots.
