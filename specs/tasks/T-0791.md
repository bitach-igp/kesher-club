# T-0791 [AUTH] Directory drift sweep: a worker job compares each SSO institution's WorkOS directory with `org.staff_idp_link` and deprovisions anyone the directory no longer lists as active
STATUS: built (2026-11-25). Dark: nothing runs while `auth.orgSso` is off, the `org-idp` binding is missing or no `orgIdp.orgs` record names a directory (the flag is read at the start and again per institution; a flag service that throws fails the cycle closed). Beyond the card: the half-guard refusal is an audit row (`institution.staff.drift_refused`, once a day per institution) and the metric `staff.drift_refused`, NOT an `ops.case`, because a new case kind needs the OpenAPI enum, the SDK and the admin types (T-0788) and would widen the contract. Absence is only believed when the list has no malformed entry and at least one active entry; a positive `active: false` always counts. Metrics added to the closed set: `staff.drift_corrected` (a count, by reason `inactive` or `missing`: any is a webhook that was lost or late), `staff.drift_refused`, `staff.directory_unlinked`. Also touched, not in the file list: `staff-deprovision.ts` (the removal body is now the public `remove`/`finish`, shared with the webhook, plus `directoryInstitutions`), `app.ts` (exposes `services.deprovision`), `packages/domain/src/metrics.ts` and its test, `jobs.test.ts` and `main.test.ts` (two rows: the 10-minute cycle and the nightly unlinked report). A removal whose role or session step failed is finished by later cycles however late: the shared `finish` writes a write-once `deprovision_finished:{institution}:{event}` marker in `ops.workflow_marker` (no migration) and stops, so a replay never revokes a newer session. A link younger than 24 hours is not removed for absence (SCIM lag); a positive inactive is never graced; the removal is bound to the link id the sweep read. The flag is re-read before each removal. A one-link institution can never be drift-removed (one of one is more than half): the guard errs on the side of keeping access, and the audit row says so.

A webhook can be lost (WorkOS retries are finite, our outage, a replay window) and the 15-minute promise of REQ-AUTH-008 is then missed silently. `OrgIdPPort.listDirectory(orgId)` ("Directory snapshot for drift checks (nightly compare against local staff table)", `org-idp.ts`) was built for this and has no caller. Cadence: the port comment says nightly; to keep the 15-minute promise even if every webhook for an institution is lost, cycle every 10 minutes for institutions with at least one active link, and nightly for a full report of directory users with no link (information only, no action). WorkOS rate limits are respected by one list call per institution per cycle.
Test first: TST-AUTH-008, simulator org IdP: (1) a linked staff member the directory lists `active: false` is deprovisioned through the SAME shared removal as T-0790 (one audit row, sessions revoked) and a second sweep changes nothing; (2) a linked staff member absent from the directory is deprovisioned and flagged `drift_missing` in the audit payload; (3) an active directory user with no link, or a directory user inactive with no link, causes no change and is only counted; (4) `PROVIDER_UNAVAILABLE` from the port changes nothing and the job reports failure for the cycle (no deprovision on an outage; an empty list from a failed read must never be read as "everyone left": a guard refuses to deprovision more than half of an institution's linked staff in one cycle and opens a case instead); (5) the job is not run when `auth.orgSso` is off, and `jobs.test.ts`'s table-versus-files check passes with the new row; (6) a lag metric `staff.drift_corrected` is emitted.
