As built:
- **Who owes.** `listCollections` returned only the month's paid items, so there was no "who owes". It now also returns `owed`: every fee item still due, whatever month it falls due in, the oldest first, with `owedTotal`. It is an additive response change. `collections.test.ts` checks an unpaid fee due next month.
- **Spend detail (REQ-INS-005).** No API serves a student's spend, and none serves consent. So I08 shows fees only, for every student, and the per-student row has no spend field at all; the test pins its keys. A consented spend view needs its own API and card; REQ-INS-005 holds in the meantime because nothing exposes spend.
- **Totals.** The page refuses to show totals that are not the sum of their rows, per currency and in bigint; it shows a "contact support" notice instead. The test goes past 2^53.
- **Export.** The browser receives the base64 envelope from a server action, decodes it to the exact bytes and saves it under the API's filename. The tests round-trip a Hebrew CSV with its BOM and an XLSX zip header.
- **`asStaff` moved.** The server-action helper (as the staff member, for their institution, with the step-up cookie) moved to `src/request.ts`, so allowances and collections share it.
