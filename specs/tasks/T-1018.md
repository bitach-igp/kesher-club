## As-built
- `approvedAgentPurchase` now takes one `ask` object and also matches the card, merchant name (first 120 characters, as stored) and country; an approval spent by this very authorisation still matches, so a retried authorisation finds it.
- A token without an id is keyed `card:<cardId>` instead of the shared `'agentic'`.
- JIT spends the approval with `consumeAgentPurchase` (one conditional update that returns whether it won) before the hold is posted and declines `AGENT_NOT_ALLOWED` if it lost. If the hold is then refused, `releaseAgentPurchase` gives the approval back so a refusal does not burn the member's yes.
- Tests: another merchant or country declines; two racing authorisations leave exactly one approved; a refused hold returns the approval. The first two fail on the old code.
- Not measured: JIT p99; the change adds one indexed update on the agent-approval path only.
- Also in this commit: the T-0658 log row, filled in.
- Review round 1: giving the approval back is best effort, so a failure of the release never replaces the error that refused the hold. Added tests: the approval returns after a funds refusal or any other error; an amount above the approval declines and a merchant name over 120 characters matches; while one authorisation holds the approval a different one declines and the same one asking again is approved with one hold; the race test now requires exactly one hold.
- Known and left: a process crash (not a thrown error) between spending the approval and posting the hold burns the approval for any new authorisation, and only a retry of the same authorisation recovers it. `openAgentPurchase` still dedupes pending asks by token, MCC and amount, so a second merchant asking the same thing waits behind the first pending ask (a safe decline).
