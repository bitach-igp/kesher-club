Source: T-0792, and the review of #421. The shape, with the reason for each part:
- `POST /institutions/{id}/sso/start` (`startStaffSso`): public, body `{deviceId}`, returns `{url, state, expiresAt}` and the binding `Set-Cookie`. Sign-in for an identity that is already linked. The institution parameter is `{id}` (the shared `Id` parameter), not `{institutionId}`.
- `POST /institutions/{id}/sso/link/start` (`startStaffSsoLink`): bearer, the SHARED required `StepUp` parameter (so the SDK asks for the step-up itself; `HEADER_OPS` row `{idempotency: false, stepUp: true}`), optional body `{deviceId, inviteToken}`. The party must be active staff of this institution or hold a valid pending invite to it; the invite is only validated here and is consumed at the callback.
- `GET /sso/callback` (`completeStaffSso`): the IdP redirects the BROWSER here, so it answers 302 to ONE fixed console URL from configuration with a single-use exchange code in the fragment (`#code=`), or `#error=refused` for every refusal (one uniform answer), with `Cache-Control: no-store`, `Referrer-Policy: no-referrer` and a `Set-Cookie` that clears the binding cookie. 404 `FEATURE_OFF` while the flag is off.
- `POST /sso/exchange` (`exchangeStaffSso`): public, body `{code}` (at least 43 characters), single use, 60 seconds, returns `{tokens: TokenPair, institutionId}`; a uniform 401 for any refusal.
- Errors per operation are in each description (FEATURE_OFF is one answer for the flag off, a malformed id, an unknown institution and one with no SSO record, so use cannot be enumerated; STEP_UP_REQUIRED for a stale step-up; 422 for bad bodies; 409 for an existing live link). No new error code; no MCP row.
- Abuse control: no application counter on the public start (a per-institution counter would let anyone who knows an id lock staff out); an edge rate rule on the ALB or WAF is a requirement before the flag turns on. `RATE_LIMITED` applies per party on the link start and per code on the exchange. Each start writes one state row, and the insert-only marker table needs a purge or TTL path.
- The ALB access log records the query string, so `code` and `state` of the callback reach the log bucket; both are single use and short lived. FOLLOW-UP before the flag turns on (no terraform here): drop the query string for `/v1/sso/callback` from the ALB access logs, or restrict those logs.
