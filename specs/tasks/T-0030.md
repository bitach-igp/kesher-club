Test first: no image has reached ECR yet. `preview.yml` is the only workflow that pushes, and its deploy job is skipped until the `AWS_CI_ROLE_ARN` repository variable exists. Nothing builds a tag for staging or prod, whose roots deploy `${var.ecr_registry}/kesher/{api,worker,admin}:${var.image_tag}`. `release.yml` runs on `workflow_dispatch` with a git ref. It assumes the CI role over GitHub OIDC, the same way `preview.yml` does, with no static keys, and builds `apps/api`, `apps/worker` and `apps/admin` from their Dockerfiles. It pushes each as `sha-<12-char commit>` to the shared account's ECR. The repositories are `IMMUTABLE`, so a second run for the same commit must skip the push, never fail it. The job summary prints the tag to pass to `terraform apply -var image_tag=…` for staging or prod. `actionlint` passes on the new workflow. `docs/setup/release.md` lists the one-time human steps below, in order, with the exact commands and where each value comes from.
