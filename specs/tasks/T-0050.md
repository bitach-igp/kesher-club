## As-built
- `.github/workflows/deploy.yml`: jobs `verify` (tag shape, run from main, the five images in ECR) and `deploy` (GitHub `environment: ${{ inputs.environment }}`). Credentials: the CI role by OIDC, then Terraform's providers assume `kesher-deploy`; the AWS CLI steps use a `--profile deploy` (and, in the prod gate, `--profile staging`) chained from the CI credentials with `credential_source = Environment`. No static keys, no IAM change (the deploy role is PowerUserAccess, which covers SSM and ECS; `modules/oidc` already trusts `environment:staging|prod` and may assume both deploy roles), so `modules/oidc` was not touched.
- Migrate ordering: a plan limited to `module.migrate` is saved, its JSON is checked to change nothing outside the module, and it is applied (new task definition revision on `kesher/migrate:<tag>`); the task is run from that exact revision and must exit 0 (30-minute cap); only then is the whole root planned (so the saved plan is not stale), shown in the summary and applied. Reasoning in `docs/setup/deploy.md`.
- Stability: `aws ecs wait services-stable` per service, then each service must have one `COMPLETED` deployment whose task definition images all end in `:<tag>`, because a circuit-breaker rollback is "stable" too.
- Smoke: the documented non-strict command per market (admin and web once, with IL), plus `--expected-tag`; no `--console-url` (the doc's can-pass-today command omits it) and no `--openapi-url`.
- SSM: `/kesher/<env>/deployed-image-tag` and `/kesher/<env>/deployed-at`, written last. The prod gate measures the age by the staging parameter's `LastModifiedDate`, so tag and time cannot disagree.
- Infra change: `ecs_service_names` output added to `envs/staging/main.tf` and `envs/prod/main.tf` (the listed files; `outputs.tf` is not on the card's list, so the output sits at the end of `main.tf`). It exists in state only after the first apply following this card.
- Decisions to confirm (fix round 1 changes (2): PAGER_ENDPOINT is required on both environments): (1) Rollback exception in the prod gate: a tag that is in the history of prod's own parameter passes without the staging hour, otherwise a rollback after staging moved on would be blocked by the card's rule. (2) Terraform variables come from the GitHub environment variable `TERRAFORM_VARS` (HCL, no secrets), and prod's `pager_endpoint` from the environment secret `PAGER_ENDPOINT`, because no tfvars exist in the repo and the card names no source. (3) A new repository variable `AWS_PROD_ACCOUNT_ID` builds the prod deploy role ARN. (4) The first apply of an environment stays manual.

## Fix round 1
Review findings and what changed:
1. **Pager endpoint on both environments.** `envs/staging` and `envs/prod` both take `pager_endpoint` with no default. The deploy job now refuses to start, before anything changes, unless the environment secret `PAGER_ENDPOINT` is an `https://` URL, on staging and prod alike. Human-steps docs and the stale "no workflow does" comments in both `envs/*/main.tf` are corrected (comment-only change to the .tf files).
2. **IAM scope, not changed here.** `modules/oidc` lets `main`, `pull_request`, `environment:staging` and `environment:prod` assume one CI role that may assume every deploy role, so the GitHub reviewers and the soak gate are not enforced in AWS. `docs/setup/deploy.md` step 5 now says so plainly (the earlier "No IAM change was needed" is gone); new card `specs/tasks/T-0070.md` (and its index row) covers per-environment CI roles or deploy-role trust on the OIDC subject.
3. **Account agreement.** `check-account.sh` runs before the first change: `account_id` and `shared_account_id` in `TERRAFORM_VARS` must equal the `AWS_*_ACCOUNT_ID` variables for the environment, and `aws sts get-caller-identity --profile deploy` must answer as that account.
4. **Soak counted for a tag staging no longer runs.** Each deploy sets `/kesher/<env>/deploy-in-progress` (after the checks and the previous-tag read) and clears it as the last act of the success record. The prod gate refuses while staging's marker exists, when staging's record names another tag, or when it is younger than an hour; the rollback exception (tag in prod's own history) is checked first and is unaffected by staging's marker.
5. **Migrate wait.** `run-migrate.sh` traps EXIT, INT and TERM and stops the task if the script ends before the task stopped itself (polling gave up, the 30-minute deadline, a cancelled run); `describe-tasks` is retried five times. A fresh OIDC session is taken before the migration, before the whole-root plan and before the service wait; the one-hour chain is documented.
6. **Soak gate before the reviewers.** The gate runs in `verify` (with its own profile step) and again in `deploy` after approval.
7. **Minor.** No `image_tag=none` hint: with no previous tag the messages say there is nothing to roll back to. "Say how to roll back" runs only when the whole-root apply was reached (`steps.apply_all.outcome != 'skipped'`); otherwise a "nothing rolled" summary. SSM reads capture stdout and stderr apart (`ssm_call` in `lib.sh`), so error text never reaches jq, and only ParameterNotFound counts as "absent": AccessDenied and the like fail the gate and the previous-tag read.
8. **Tests.** The logic moved into `tools/release/deploy/*.sh`; `deploy-workflow.test.mjs` now runs them with a stub `aws` (48 tests in `tools/release`): `check-plan.sh` against sample plan JSON (outside update, delete-create, read, no-op, prefix lookalike), `run-migrate.sh` (exit 0, non-zero, missing exit code, wrong image, retries, persistent failure, deadline and SIGTERM stopping the task), `check-services.sh` (rolled back, wrong image, two deployments, in-progress, failed, no containers, one bad service among good ones), the prod gate (epoch and ISO timestamps, AccessDenied on each of the three reads, marker, other tag, rollback), `check-account.sh` and `configure-profiles.sh`. The structural tests that remain check order and presence.

Still unverified: everything in the first As-built list (nothing ran against AWS or GitHub; no actionlint or shellcheck), and now also the scripts' behaviour against the real CLI's output shapes (the stubs encode what the CLI is believed to print), `ecs wait` exiting 255 on timeout, and bash trap delivery when GitHub cancels a run.
