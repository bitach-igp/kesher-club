## As-built
- `.github/workflows/deploy.yml`: jobs `verify` (tag shape, run from main, the five images in ECR) and `deploy` (GitHub `environment: ${{ inputs.environment }}`). Credentials: the CI role by OIDC, then Terraform's providers assume `kesher-deploy`; the AWS CLI steps use a `--profile deploy` (and, in the prod gate, `--profile staging`) chained from the CI credentials with `credential_source = Environment`. No static keys, no IAM change (the deploy role is PowerUserAccess, which covers SSM and ECS; `modules/oidc` already trusts `environment:staging|prod` and may assume both deploy roles), so `modules/oidc` was not touched.
- Migrate ordering: a plan limited to `module.migrate` is saved, its JSON is checked to change nothing outside the module, and it is applied (new task definition revision on `kesher/migrate:<tag>`); the task is run from that exact revision and must exit 0 (30-minute cap); only then is the whole root planned (so the saved plan is not stale), shown in the summary and applied. Reasoning in `docs/setup/deploy.md`.
- Stability: `aws ecs wait services-stable` per service, then each service must have one `COMPLETED` deployment whose task definition images all end in `:<tag>`, because a circuit-breaker rollback is "stable" too.
- Smoke: the documented non-strict command per market (admin and web once, with IL), plus `--expected-tag`; no `--console-url` (the doc's can-pass-today command omits it) and no `--openapi-url`.
- SSM: `/kesher/<env>/deployed-image-tag` and `/kesher/<env>/deployed-at`, written last. The prod gate measures the age by the staging parameter's `LastModifiedDate`, so tag and time cannot disagree.
- Infra change: `ecs_service_names` output added to `envs/staging/main.tf` and `envs/prod/main.tf` (the listed files; `outputs.tf` is not on the card's list, so the output sits at the end of `main.tf`). It exists in state only after the first apply following this card.
- Decisions to confirm: (1) Rollback exception in the prod gate: a tag that is in the history of prod's own parameter passes without the staging hour, otherwise a rollback after staging moved on would be blocked by the card's rule. (2) Terraform variables come from the GitHub environment variable `TERRAFORM_VARS` (HCL, no secrets), and prod's `pager_endpoint` from the environment secret `PAGER_ENDPOINT`, because no tfvars exist in the repo and the card names no source. (3) A new repository variable `AWS_PROD_ACCOUNT_ID` builds the prod deploy role ARN. (4) The first apply of an environment stays manual.
