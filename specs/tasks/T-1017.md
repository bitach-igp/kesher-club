As built:
- **The consent screen** is `/connect/{id}` (`app/connect/[id].tsx` and `connect.model.ts`).
  - Scopes are grouped See / Act for you / Propose payments for you to approve, each in plain words, with Hebrew mirrored.
  - The propose tier starts unticked, and its group says nothing moves without a passkey approval.
  - The assistant's name and home page are shown as text, and the home page is not a link.
  - "Connect with passkey" calls approve: the API client runs the step-up (`HEADER_OPS`), and a stale step-up shows a banner and retries. "Not now" denies.
  - On the web the browser goes to the returned redirect in the same page. A new tab, which `Linking.openURL` opens on react-native-web, would leave the member on the consent screen.
- **Consent survives sign-in** (`_layout.tsx`, `resumable`). On the web build a full page load starts signed out, so a member arriving from an assistant used to land on Home after signing in. The layout now remembers `/connect/{id}` while signed out and resumes it once after sign-in. Nothing else resumes.
- **Loopback redirect URIs** (`cimd.ts`, `allowedRedirectUri`). Redirect URIs may be https, or http on `localhost`, `127.0.0.1` or `[::1]`, as OAuth 2.1 §8.4.2 and RFC 8252 allow native and command-line clients (MCP desktop clients redirect to a loopback port). Fragments and credentials are refused. T-1003 had refused all http.
- **The demo assistant** (`apps/simulators/src/assistant.ts`) mounts on the panel under `/assistant`: `client.json`, `start` (a 302 with S256 PKCE and a state), `callback` and `status`.
  - It holds tokens in memory, and `RunningDev.assistant.accessToken()` gives T-1013 its bearer. The page and the status never show a token.
  - It takes the API's issuer separately from its address, so `resource` matches when the API listens on another port (tests).
- **`dev.ts`** answers `assistant.kesher.test` itself, with a public-looking address and the document from memory. Every other host goes to real DNS and fetch, so the SSRF guard is unchanged. Consent goes to the first `DEMO_WEB_ORIGINS` entry plus `/connect`.
- **Checked in Chromium** against the T-0031 stack and the Expo web build:
  1. Dana signs in.
  2. `/assistant/start` lands on `/connect/{id}`, where sign-in returns her after the reload.
  3. She unticks card status and connects with her passkey.
  4. The panel says "Connected. Granted: balances:read transactions:read.", and `/assistant/status` agrees.
