# T-0038 [SETUP] The AuthPort contract measures OTP expiry on the port's own clock, not the wall clock
REQ: REQ-AUTH-001 (enabling; found locally on T-0644) · Sprint: 15
Files: packages/ports/src/auth.contract.ts, packages/ports/src/auth.simulator.test.ts, specs/tasks/T-0038.md, specs/tasks/README.md
Test first: `packages/ports/src/auth.simulator.test.ts` as it stands, on any day after 2026-11-01.

**What failed.** `@kesher/ports#test`, `auth.simulator.test.ts` > "AuthPort contract: simulator > starts an OTP with a
5-minute expiry and 5 attempts": *expected 1793523900000 to be greater than 1793625310124*. It fails on `main` for
everyone, and so on every PR's "lint · typecheck · unit · trace" job.

**Why.** The contract compared `expiresAt` with `Date.now()`. The simulator runs on `fixedClock()`
(`2026-11-01T09:00:00Z`), so its OTP expires at 09:05 that day; once real time passed it, the assertion could never
hold. The test was a time bomb that went off on 2026-11-01 09:05 UTC. It also never checked the five minutes its name
promises: any future expiry passed.

**Change.**
- `AuthContractOptions` gains `now?: (port) => Date`, the port's own clock, beside `otpCode(port)`; real time when
  omitted.
- The contract reads that clock before and after `startOtp` and asserts `expiresAt` is exactly five minutes after it.
- The simulator suite passes `now: (port) => port.clock.now()`.
- No product code changed.

**Evidence.**
- `@kesher/ports`: 162 of 162 pass; the failing test passes on any date.
- The test now bites: with the simulator's `OTP_TTL_MS` set to four minutes it fails; before, it passed.
