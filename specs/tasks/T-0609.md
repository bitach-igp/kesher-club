Test first: TST-INS-003, TST-INS-004. I07 needs "Schedules, preview, run, history", but the contract has only `POST /institutions/{id}/allowance-runs`. Add `GET /institutions/{id}/allowance-schedules`: each schedule's amount, currency, cadence, cohort and next date. Add `GET /institutions/{id}/allowance-runs`: each run's date, state (`previewed`, `awaiting_second_approval`, `running`, `completed`, `failed`), total, members paid and failed, and who requested and approved it (staff display names only). Both are org-staff only and scoped to the staff member's institution. The tests cover: another institution's staff get 404; a run waiting for its second approver lists its first approver; the totals equal the run's journals (bigint).
Done when: listed tests pass; Spectral clean; `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm trace` green; only listed files touched
Out of scope: creating or editing schedules (I07 create is a later card). Stop and ask on conflict with the spec.

As built:
- **States keep the contract's existing words.** The run states reuse the `AllowanceRun.status` enum the POST already answers: `preview`, not `previewed`. One word per state across both operations.
- **Display names.** Staff have no stored names, so a person appears as their institution role and the phone's last four digits ("Finance •••• 0109"). Someone no longer on the staff appears as "Former staff". No party id or full phone leaves the endpoint, and the test checks the response text for both.
- **Approvers.** They come from the run's `allowance_run` approval decisions, oldest first. Under ₪5,000 the requester's own decision approves, so they appear once. Over it, a waiting run lists the requester, and the completed run adds the second finance member.
- **`paidTotal`.** It is summed from the settled journals' institution-side postings (bigint text); `total` is the planned run total. They differ only on a run with failed payments.
- **`nextDate`.** Today for a schedule that never ran (a preview does not count). Otherwise a week or a calendar month after its last run, clamped to the month's last day, and never before today. A one-off that ran has none.
- **Access.**
  - Both reads need an org role. Staff of another institution get 404; a plain member gets 403.
  - Both reads sit behind `institutions.money`, like the run itself: a console with institution money off shows the feature as off.
