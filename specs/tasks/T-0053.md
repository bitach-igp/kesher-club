Emit CloudWatch Embedded Metric Format lines (no agent, no SDK call, so no new dependency and no network on the authorisation path): `jit.decision_ms` and `jit.error`, `webhook.lag_s` (oldest unapplied `ops.inbound_event`), `job.failure{job}` and `job.age_s{job}` from the scheduler, `recon.break_open_usd` and `recon.break_oldest_h`, `transfer.stuck{state}` (oldest non-terminal transfer age), `provider.error{port}`. Dimensions are bounded (market, port, job): never a member, account or transfer id. Tests: a JIT decision emits one line with a duration; a failing job emits `job.failure`; the dimension set is closed (a test fails on an unknown dimension).

As built:
- `packages/domain/src/metrics.ts` (exported from `index.ts`): `createMetrics({ write?, now?, namespace? })` writes one CloudWatch Embedded Metric Format line per call on stdout (namespace `Kesher`); `stdoutMetrics` is the default; `guarded(m)` wraps any injected emitter so that no method can throw. No SDK, no network, no new dependency. `METRIC_DEFS` is the closed table of metric, unit and dimensions; `METRIC_DIMENSIONS` is `market, port, job, state` and nothing else. `validateDimensions` throws on an unknown dimension or on a value that is not a bounded name (a UUID, a hex or long digit run, a name over 40 characters; `market` must be IL or US, `state` a transfer state); `put` never raises and writes NO line for a metric given a dimension it does not carry. A member, account or transfer id cannot become a dimension.
- Metrics and dimensions (T-0054 alarms must match these exactly): `jit.decision_ms` and `jit.error` (no dimensions, one line per decision; `jit.error` is 0 or 1, so the error rate is its Average), `webhook.lag_s{market}`, `job.failure{job}`, `job.age_s{job}`, `recon.break_open_usd` and `recon.break_oldest_h` (no dimensions), `transfer.stuck{state,market}`, `provider.error{port}`. `market` was added to `webhook.lag_s` and `transfer.stuck` (the card lists `transfer.stuck{state}`) because each market's worker emits them and the two would otherwise overwrite each other.
- Where each is emitted:
  - `jit.decision_ms`, `jit.error`, `provider.error{port=card-issuing}`: `JitService.decide` (`apps/api/src/cards/jit.ts`), once per decision after the outcome is fixed. `jit.error` is 1 when the decision failed closed (a throw or the budget overrun), so a plain decline is not an error. The emitter is injected as `JitDeps.metrics` (default stdout) and guarded, so it cannot change the decision. `provider.error` is emitted only when `CardIssuingError` is what failed the decision; other ports have no emit point yet.
  - `job.failure{job}` and `job.age_s{job}`: `Scheduler.runOnce` (`apps/worker/src/scheduler.ts`; 4th constructor argument, default stdout). A run that throws emits `job.failure` and the seconds since the job last finished without throwing (since the scheduler started if never); a run that did its work emits `job.age_s` 0. A skipped tick (lock held elsewhere) and a daily job's idle tick emit nothing, so a daily job's age is read at its own run.
  - `webhook.lag_s{market}`: `InboundEventStore.reportLag` (`apps/api/src/webhooks/store.ts`), the age of the oldest unapplied verified `ops.inbound_event`, 0 when none. It is a gauge, so it needs a periodic sweep: the worker job `metrics-market` (every 60 s, market scope, `apps/worker/src/jobs.ts`).
  - `transfer.stuck{state,market}`: `TransferService.reportStuck` (`apps/api/src/transfers/service.ts`), per non-terminal state the seconds since the oldest transfer in it last changed state (`updated_at`); a state with no transfers emits nothing. Also from `metrics-market`. Note `pending_hold` is normally up to 2 hours.
  - `recon.break_open_usd` and `recon.break_oldest_h`: `reportReconBreaks` in `jobs.ts`, run by the worker job `metrics-recon` (every 60 s, club scope). Open means the case is `open` or `investigating`. `recon.break_open_usd` is the sum of |partner - ledger| over USD breaks (a side that is missing counts as 0), whole dollars as a number made from bigint minor units by `minorToNumber`: a number for an alarm to read, not a money value, never written back or converted. `recon.break_oldest_h` is the age in hours of the oldest open case of any currency. Both are 0 when nothing is open.
