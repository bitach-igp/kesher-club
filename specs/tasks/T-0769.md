Because T-0761 made `recordCreditBegan`, `recordCreditOutcome` and `creditAttemptState` the only code that touches the credit markers, the switch is those three function bodies: `putMarker('credit_began', transferId, attempt, creditKey)` and `putMarker('credit_outcome', transferId, attempt, outcome)` (the outcome is stored as the bare `credited|pending|refused` value, not the `{creditKey}:{status}` suffix, so the string parsing that T-0761 kept for compatibility is deleted). The `external_ref` unique `(provider, external_id)` no longer constrains a credit key, which is the intent. Credit markers are keyed by the transfer id, which implies the provider, so no provider goes into `kind`; `value` is not unique, so a repeated `credited|pending|refused` across transfers is fine. Verified that nothing else reads `funding_credit%` rows (grep across apps, packages, tools, handoff).
