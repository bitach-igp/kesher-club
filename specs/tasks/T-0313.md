## As-built
- Migration `billing/0005_one_membership_per_member.sql`: `create unique index membership_one_open_per_member on billing.membership (member_party_id) where status <> 'cancelled'` (plain, not concurrent, like the other partial unique indexes in this schema; `atlas.sum` refreshed with a script that reproduces the existing sums exactly, because the Atlas CLI could not be downloaded in the cloud session).
- `MembershipService.create` now refuses a member who already holds a non-cancelled membership **before any vendor call** (the `held` query moved here from `createForCaller`, so the invite path is covered too). The index settles the true race: a unique violation is either the same key racing itself (the winner is returned, as before) or the member taken by another request. In the second case the subscription just made is ended at once (`cancel(..., 'now', 'lost:<sha256 of the key>')`, a short key within the 128-character limit), the key is remembered in `ops.external_ref` (`membership_lost_key`) so a retry of it is refused with 409 instead of replaying the ended subscription at the vendor, and a failed cancel opens an `ops.case` (`membership_orphan_subscription`) because that subscription would keep billing. The vendor call still precedes the insert (changing that order is a larger change).
- Invite acceptance for a member who already holds a membership now answers 409 and the invite stays open; the invite flow's own rules are out of scope.
- Tests: `memberships.test.ts` (PGlite: a second create refused before the vendor; a cancelled membership does not block a new one; a lost race ends its subscription, refuses its key afterwards and opens a case when the cancel fails) and the new gated `memberships.pg.test.ts` (five parallel creates on real Postgres: one row, four subscriptions ended). Run locally on Postgres 16: 1 passed. The desktop handoff `handoff/desktop/T-0313-one-membership-per-member.md` repeats it and checks that a direct duplicate insert is refused.
