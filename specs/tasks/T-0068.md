# T-0068 [SETUP] The console's large requests pass the WAF: a roster import is not blocked at 8 KB
REQ: — (enabling; found in the T-0047 review; after T-0047) · Sprint: 16 deploy
Files: infra/terraform/modules/alb/main.tf, infra/terraform/modules/alb/variables.tf, infra/terraform/envs/staging/main.tf, infra/terraform/envs/prod/main.tf, infra/terraform/tests/alb.tftest.hcl, docs/setup/release.md, specs/tasks/T-0068.md, specs/tasks/README.md, apps/api/src/infra-contract.test.ts
Test first: the ALB's WAF runs `AWSManagedRulesCommonRuleSet`, whose `SizeRestrictions_BODY` rule blocks request bodies over 8 KB. The console's roster import (`apps/console/src/roster-import.ts`, `MAX_BYTES` 900 KB) is relayed to the API through that ALB (T-0047), so a large import would get 403. Either exempt that rule for the console's import route (a scope-down on the host and path, not the rule group) or send the console's calls to the API over an internal path that does not cross this WAF. `terraform test` asserts the chosen exemption or route and that the rule group is otherwise unchanged.
Done when: listed tests pass; CI's terraform job green; a 900 KB roster import is accepted in staging (desktop or staging check); only listed files touched
Out of scope: other WAF rule tuning; the client-address question (T-0069). Stop and ask on conflict with the spec.

## As-built
`apps/api/src/infra-contract.test.ts` was added to the Files line (the repo-level proof, below). `specs/tasks/README.md` needed no change.

- Option chosen: a scope-down on the public ALB's WAF, not an internal path. An internal path would need a second listener or ALB, a new security-group path, a DNS change in the console's `CONSOLE_API_URL` and would move the NAT/client-address question (T-0069) rather than leave it; the WAF change is one variable and two rules, reverts by setting the variable to null, and leaves every other route as strict as before.
- `modules/alb`: new variable `large_body_route` (`host`, `path_regex`, `method` default `POST`), default `null` = no exemption, so the module is unchanged for the admin ALB and for any caller that does not pass it. When set: (1) the `AWSManagedRulesCommonRuleSet` rule gains one `rule_action_override` of `SizeRestrictions_BODY` to `count` (the group stays, its `override_action` stays `none`, no other rule is overridden, the other two groups are untouched); a counted rule still labels the request `awswaf:managed:aws:core-rule-set:SizeRestrictions_Body`. (2) New rule `body-size-outside-exempt-route` (priority 50, after the groups at 10 to 12, before the webhook rule at 100) BLOCKs a request that carries that label unless it is POST (method), on the exact host (Host header, lowercased) and a path that fully matches the regex. So the net effect is: every route blocks bodies over 8 KB exactly as before, except that one.
- Both envs pass it on `module.alb` only (not `admin_alb`): host `local.market_hosts["il"].api` (the host `CONSOLE_API_URL` names, T-0047), path `^/v1/institutions/[^/]+/rosters$` (OpenAPI `importRoster`, `POST /institutions/{id}/rosters`, served under `/v1`). The US API host is not exempted: the console calls the IL host only. If a US-host console call is added, it needs its own decision.
- Proof: `infra/terraform/tests/alb.tftest.hcl` (new, `mock_provider "aws"`, plan) asserts the default has no override and no companion rule, and with a route: the common rule set is still there with exactly one override, `SizeRestrictions_BODY` to count, no other group overridden, the blocking rule exists after the groups, matches the label, and negates host + path + method (three statements). `apps/api/src/infra-contract.test.ts` carries the same facts as text checks (5 of its new cases fail on main) plus: the exemption is on the public ALB only, in both envs, with the path the console posts to. No `terraform` binary exists in this session, so `terraform test`, `fmt` and `validate` were NOT run here: CI's terraform job is the real check of the `.tftest.hcl` (in particular the set/list indexing in its expressions) and of the label key spelling.
- Owner apply note: `terraform apply` in staging then prod updates `aws_wafv2_web_acl.this` in place (rule list changes; no replacement, no downtime). After the staging apply, POST a roster of about 900 KB (`cohorts`/`rosters` import in the console) and expect 200; POST the same size to any other route, or to the roster path on the `us` host or with a different method, and expect 403. Look for `SizeRestrictions_BODY` as a counted rule and `body-size-outside-exempt-route` as the blocking one in the WAF log group. Not verified by me: the 900 KB acceptance (desktop or staging check, per the card). ALB WAF inspects only the first 8 KB of a body, so the other body rules still see only that.
