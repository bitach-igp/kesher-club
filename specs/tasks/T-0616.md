Test first: TST-INS-008. Institutions may run allowances on credit (decision 2026-10-20), but only up to a limit Kesher set on purpose. Each institution has a credit limit per currency: ₪0 or $0 until one admin proposes a limit and a second approves it (approval kind `credit_limit`, audited). An allowance run, and its preview, refuses with INSUFFICIENT_FUNDS when it would take the account below minus the limit, and says what the account holds, the limit, and what the run needs. The check and the payments run under one lock per institution, so two runs cannot both pass on the same headroom. Payouts (T-0527) keep never going below zero: the credit line pays students, not suppliers. The tests cover: ₪1,000 held with a ₪5,000 limit refuses a ₪7,000 run and pays a ₪6,000 one, leaving −₪5,000; without an approved limit, a run larger than the balance is refused; one admin's proposal changes nothing; two concurrent runs on the last headroom pay once.
Done when: listed tests pass; Spectral clean; `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm trace`, `pnpm db:lint` green; desktop handoff requested; only listed files touched
Out of scope: interest or fees on credit, repayment schedules, console screens. Stop and ask on conflict with the spec.

As built:
- `InstitutionCredit` (`institutions/credit.ts`) keeps the limits: each approved one is a new row in `ops.institution_credit_limit` (club_app may select and insert, never update), audited as `institution.credit.set` with the old and new limit in the payload. Approval kind `credit_limit` needs two different admins.
- The workflow gained one activity, `startRun`, in place of `recordRun(p, 'running')`. It checks the headroom and marks the run running in one transaction holding `pg_advisory_xact_lock` for the institution. Headroom is balance + limit − what other running runs still owe; a rerun needs only what it has not paid yet.
- The runs handler checks the same headroom, without the lock, before a preview or a first request, so finance hears "the run needs ₪7,000.00; the account holds ₪1,000.00 with a credit limit of ₪5,000.00" before anyone is asked to approve. The problem body carries `balance`, `creditLimit`, `reserved` and `needed` as Money.
- Tests that pay allowances from an empty account now fund it (`allowance-runs.test.ts`, as a settled deposit journal) or give it a credit line (`workflow.test.ts`).
- A run that crashes while `running` keeps its unpaid remainder reserved until it is rerun; that is the safe side. There is no reject for a proposal: it expires after 7 days like every approval.
