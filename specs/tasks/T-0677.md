## As-built
- `layout.tsx` imports `@kesher/tokens/css` and a new `app/styles.css` (the console's approach, T-0675) and reads the area list from `src/ui/nav.ts` (A01 to A09 and A12, in the order they had; `areaLabel` looks one up). The inline theme-literal stylesheet is gone, including the one `#fff` (the danger button now uses the surface token). Every class the pages use is kept: `.shell`, `.banner`, `.tag` (red, amber, green and the status words), `.button`, `button.primary`, `button.danger`, `.card`, `.grid`, `.muted`, `form.inline`, `dl`; table, nav and heading rules keep their shape but read the token type scale and logical edges, so sizes moved with it (h1 22px to 32px, h2 16px to 17px, body 15px to 16px, table headings and the nav code 12px to 11px, tags 12px to 13px). The admin now follows the system's dark theme through the tokens (it was light only); `color-scheme: light dark` makes native controls follow, and a focus ring is added.
- Home: the three counts are `.stat` tiles in a `.stats` row (value large, the link and detail under it).
- Verified with a real `next build` of the admin app: it compiles and the output CSS carries the token variables.
- Not covered: a render of the pages. Two nav links (`/ledger`, `/legal`) have no page yet; that was already true and is not changed here.
