Test first: post a journal institution_master → the institution's payout-reserve for 1,000 ILS (by hand in the test): on main the account type does not exist; with it, today's statement and export would show a 1,000 ILS payout that never left.
- Forward-only migration (see the `club-ddl` skill): `alter type ledger.account_type add value 'payout_reserve'` in its own migration file (a new enum value cannot be used in the transaction that adds it); no grants change, the ledger stays insert-only. `atlas migrate hash`, `pnpm db:lint`.
- `accounts.ts`: `institutionPayoutReserveAccount(institutionId, currency)` (credit-normal, owned by the institution, provisioned on demand like `institutionHoldAccount`), `institutionReserved(...)`. `institutionBalance` stays the master balance, meaning *available*: payouts' funds check, ACH, deposits, collections, loads and allowance runs keep reading it unchanged.
- **Statement** (REQ-INS-021) and **export** (REQ-INS-006): the institution's money is master + payout-reserve. A journal whose only institution-side postings are master ↔ payout-reserve nets to zero and is not a movement row; a payout appears once, when it posts from the reserve to the rail. Opening and closing balances include the reserve, still reconcile opening → closing, and the export still equals the statement. Show the closing reserved amount as its own figure.
- **Dashboard** (REQ-INS-017): master balance = what the institution owns (master + reserve), plus `available` and `reserved` per currency (contract change: see the `club-openapi` skill, regenerate the SDK).
- **Credit headroom**: unchanged code (reads master = available): money reserved for a payout is not headroom. Add the test that says so.
**Tests.** with a hand-posted reserve and its release in the same month: statement and export show no payout row, unchanged opening/closing, export equals statement; with a reserve open at month end: closing includes it and `reserved` shows it; dashboard owned = available + reserved; credit headroom drops by the reserve. Money asserts in bigint. Real Postgres via the handoff (migration applies on all schemas; one reserve posting accepted).
Done when: listed tests pass; `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm trace`, `pnpm db:lint`, Spectral green; handoff PASS; only listed files touched. If the diff passes about 400 lines, split the dashboard contract change into its own card and say so in the PR.
Out of scope: posting reserves from payouts (T-0550); console UI for the new dashboard fields. Stop and ask on conflict with the spec.

## As-built
- **Migration `ledger/0027_institution_payout_reserve.sql`:** `alter type ledger.account_type add value 'payout_reserve'` alone in its file, with `squawk-ignore require-enum-value-ordering` (account types are never compared by order). No grants change. `atlas.sum` refreshed with the script that reproduces the existing sums exactly (the Atlas CLI cannot be downloaded in the cloud session).
- **`accounts.ts`:** `AccountType` and the credit-normal set gain `payout_reserve`; `institutionPayoutReserveAccount(inst, currency)` provisions on demand; `institutionReserved(...)` reads it. `institutionBalance` is unchanged: the master, meaning *available*, so payouts' funds check, allowances, ACH, deposits, collections, loads and credit headroom read it as before.
- **Statement:** the institution's money is master + reserve. Opening and rows are summed over both accounts per journal and a journal netting to zero (money moving between them) is not a row (`having sum <> 0`); a payout appears once, when it posts out of the reserve. New `reserved` figure (closing reserve) on the statement, its export response and as a last `reserved` line in the CSV/XLSX; the existing CSV/XLSX assertions were updated for that line.
- **Export:** same rule (master + reserve per journal, zero-net journals dropped); a payout posted from the reserve is one row.
- **Dashboard:** `balances` = what the institution owns (master + reserve); new `available` and `reserved` arrays. Contract change (statement `reserved`, statement-export `reserved`, dashboard `available` and `reserved`): added response fields, regenerated SDK, Spectral clean.
- **Credit headroom:** code unchanged (reads the master = available); a test says reserved money lowers it by exactly the reserve.
- **Tests:** statement (reserve and release in one month = no row; open reserve at month end shown as reserved; payout appears once, in the month it goes out), export (same), dashboard (owned = available + reserved), credit (headroom drops by the reserve). The account stays empty until T-0550 posts to it. Handoff `handoff/desktop/T-0555-payout-reserve-account.md` checks the migration and the new value on real Postgres 16.
