The verifier is `WorkOsOrgIdPAdapter.verifyWebhookSignature` (`WorkOS-Signature: t=..., v1=...`, 5-minute tolerance); the processor maps the event through the port's `parseScimEvent` normalisation and the link from T-0789.
Behaviour: bind `workos` only when `registry.bindingFor('org-idp', market)` exists and `auth.orgSso` is on at boot and re-check the flag in the processor (a flag turned off later stops processing, events stay pending for replay). `dsync.user.deleted`, or `dsync.user.updated` with `active = false` (op `deactivate`), finds the staff row through `StaffIdpLinks.find(institutionId, subject)` (the institution comes from the directory id in the payload, mapped through the adapter's per-org config, never from the payload's free text), sets `org.staff.active = false`, removes the `org_*` role (the shared removal body), calls `tokens.revokeAll(partyId, 'idp_deprovision')` so the access token and every refresh family die now instead of at the next sign-in, and writes an audit row (`institution.staff.deprovision`, actor system, the event id as reason key). Rules a reviewer checks: an unknown subject is a recorded no-op (200, nothing moves); a repeat of the same event id changes nothing (store dedupe plus idempotent update); the LAST ACTIVE ADMIN is deprovisioned anyway (the IdP is the authority; skipping would keep a removed person's access) and the processor raises an audit row `institution.admin.none` plus a notification to Kesher staff so the institution is not left with no admin unnoticed; `create` and `update` events never grant or raise a role (provisioning stays with the institution's own admins, T-0643); event text (names, emails, groups) is untrusted and is never logged or used as an instruction.
Test first: TST-AUTH-008, with the simulator org IdP (`SimulatorHost`, no WorkOS network): (1) a correctly signed deactivation for a linked staff member sets `active = false`, strips the role, revokes sessions (their next call with the old token answers 401) and writes one audit row, all in one request; (2) a forged signature and a signature older than 5 minutes answer 401 and nothing moves; (3) the same event id twice moves nothing the second time; (4) an unknown subject and an unlinked staff member are no-ops, 200; (5) the last active admin is deprovisioned and the alert row exists; (6) a `create` event does not create or raise staff; (7) with `auth.orgSso` off the route answers 404 and the event is not stored; with the flag turned off after boot the processor leaves the event pending; (8) `occurredAt` older than 15 minutes at processing is metered (`staff.deprovision_lag_s`) so the 15-minute promise is observable.
