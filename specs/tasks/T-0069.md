## As-built
Added to the Files line: `apps/api/src/infra-contract.test.ts` (its T-0068 test counted one `large_body_route` and sliced the admin ALB up to `module "api"`, both now wrong; it also gains the T-0069 contract test, since there is no terraform binary here). `infra/terraform/modules/alb/main.tf` and `variables.tf` gain `allowed_security_group_ids` (and `outputs.tf` two counts the root test reads) (review fix; see the trust boundary below) and `tests/alb.tftest.hcl` tests it.

Chosen option: the internal route (the card's first). Each env gets `module.internal_alb` (internal, private subnets, wildcard certificate), a listener rule sending host `api-il-internal.<domain>` to the IL API target group, a task security-group rule for that ALB on port 3000 (the ecs-service default), and a Route 53 alias. `CONSOLE_API_URL` is `https://api-il-internal.<domain>/v1`. The internal ALB also carries the roster-import exemption (T-0068) for its host (otherwise its WAF would 403 a 900 KB import) and a raised per-IP rate limit (100000 per 5 minutes; the source address there is the console task, so the old 2000 would throttle all staff together).

The API change is needed with the route: the internal ALB appends the console task's private address, so reading the last entry would record that. `clientIp` (`us-banking.ts`) now skips ONE trailing private address (RFC 1918, loopback, link-local, CGNAT, IPv6 ULA) and takes the entry before it; it never returns a private address. Why a client cannot spoof it: the internet-facing ALB appends the real TCP peer, which is public (the NAT gateway's address is public too), so a client's own entries are never last and a private entry it plants is never skipped; only a host inside the VPC can connect to the internal ALB. No header is trusted by name and no secret or configuration is added. Console side: `api.ts` already forwards the browser's address (the last entry its own ALB appended) as the only entry; only its comments changed. Tests: `us-banking.test.ts` (direct client; relayed by the console records the staff member; forged private entries; one hop only; no private address), `infra-contract.test.ts` and `markets.tftest.hcl` (console URL is the internal host and not the public one; listener rule, record and security-group rule).

Not verified: there is no `terraform` binary here, so `fmt -check`, `validate` and `terraform test` were not run (HCL written to match neighbouring blocks, aligned for `fmt`; CI's terraform job is the real check). An unplanned apply was not tried: a second listener rule on the API target group, the new ALB and the alias are new resources, nothing existing is replaced. The WAF limit of 100000 and the single trailing-hop rule are my choices, not measured. The admin app still calls the public `api-il`/`api-us` hosts through the NAT gateway (`ADMIN_API_URL_*`); that is not the console and the card names the console, so it is a follow-up if admin calls should stop sharing the NAT's rate limit (the admin app sends no client address). The US API host has no internal route (the console picks IL only today).

**Trust boundary (review fix).** `contactIp` (the bank application's consent evidence) is only as trustworthy as the set of senders the internal ALB admits, because the API believes the address a private-hop sender forwards. The module's default internal ingress is the whole VPC CIDR, which includes Client VPN users (source-NATed into VPC addresses), who could then forge `x-forwarded-for`. So `module.internal_alb` sets `allowed_security_group_ids = [module.console.security_group_id]`, which REPLACES the CIDR rule: only the console's tasks may connect (one rule per group, by `count` so an id unknown at plan time does not fail the plan). Anything else that must call the internal host later has to be added there deliberately, and is then trusted to forward a truthful address. The admin app is not admitted.
