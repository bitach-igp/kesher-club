Test first (ids TST-WAL-003 and TST-LED-003 for the mirror items, TST-INS-006 for the rest; one failing test per line, written before the change):
1. Ledger failure wrapping. A `KeyLedger` that throws on `begin`, `complete` or `fail` inside `member-accounts.ts` and `institution-banking.ts` is answered with the adapter's `PROVIDER_UNAVAILABLE` (a `DomainError`, no raw driver message, no key in the text), never a bare `Error` or an unhandled rejection; a vendor call that already succeeded is not repeated on the replay.
2. Atomic claim in `funding.ts`. Two concurrent calls with different idempotency keys and the same colliding title make one vendor create and one `found` answer (or one `ambiguous`), never two creates: the claim of the title is one atomic step (the ledger's insert-if-absent), not a read followed by a write. Test with two `Promise.all` calls over the in-memory ledger and a fake that counts creates.
3. `searchParams.delete` re-serialisation. `funding.ts` (`u.searchParams.delete('intentId')`, around line 181) rewrites the whole query string (re-encodes `+` and spaces, reorders nothing else); a URL whose other parameters carry `%20`, `+`, `~` or a repeated key is returned with those bytes unchanged apart from the removed `intentId`. Strip the one parameter by string, not by `URLSearchParams.toString()`.
4. `isPublicIp` in `packages/ports` (`funding.ts`): `2002::/16` (6to4, which embeds an IPv4 that may be private) and `2001:db8::/32` (documentation) answer not public, as do the already-covered ranges; a 6to4 address whose embedded IPv4 is public is still refused (we do not decode it). Table test, one row per range, plus a public IPv6 that stays accepted.
5. `readBack` ordering and `continue`. In `mirror.ts` a list row older than `since` is skipped with `continue`, not `break`: the walk no longer assumes newest-first. A fake that lists oldest-first, and one that interleaves old and new rows, both find the match.
6. `readBack` without `since`. It scans a bounded number of pages (a named constant, default 20 pages of the fake's page size) and answers `ambiguous` with the scan-limit reason rather than walking the whole list; a test with 25 pages and the match on page 24 shows the limit; with `since` the walk is unchanged.
7. `listBookPayments` termination. A page that adds no new id (a vendor that ignores `offset`, or the fake with `ignoreOffset`) stops the loop and answers what it has plus a `truncated: true` flag; today it stops only on an empty page and spins. The fake gains an `ignoreOffset` switch for this test.
8. `mirror.ts` header comment states the as-built behaviour (list by memo, bounded by `since`, `Rejected` read as refused); a lint-level check is not needed, the diff shows it.
9. `bookWireKey` prefix argument. `bookWireKey(prefix, key)` in `book.ts` takes the namespace as an argument; the mirror adapter passes `mirror:`, and T-0704's wallet credit will pass its own. A mirror key and a credit key with the same workflow id derive different wire keys; both stay UUID v4 (T-0734); the existing mirror wire keys are unchanged (pin one value in a test).
10. Typed `metadata` on the port `Load`. `packages/ports/src/funding.ts` gains an optional `metadata?: Readonly<Record<string, string>>` on the port `Load`, the simulator fills it, and the adapter maps the vendor's field into it; the cast in `apps/api/src/.../loads.ts` that reads it is removed in the card that owns that file (not touched here, so the one-card-one-file-set rule holds: leave a `// TODO(T-0735)` there only if T-0703's owner agrees). Test: the contract returns `metadata` for a load created with it, and `undefined` otherwise.
