Test first: Terraform deployed `kesher/admin:<tag>`, but no Dockerfile or workflow built it, and its health check pointed at `/api/healthz`. The console has no such route, and the proxy gates that path, so the load balancer would have got 403 from inside the VPC: the service could never turn healthy. `infra-contract.test.ts` now fails unless staging and prod health-check `/healthz`, the console serves `app/healthz/route.ts`, and `PROXY_MATCHER` leaves that path alone. `/healthz` answers 200 only when the config loads. The image is two stages: Next's `standalone` output, traced from the repository root, runs as `node` with no settings baked in. The preview workflow builds and pushes `kesher/admin` next to `kesher/api` and `kesher/worker`. The real `docker build` and container runs are a desktop handoff.
Done when: listed tests pass; `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm trace` green; CI's admin build and terraform job green; the desktop handoff reports the expected output; only listed files touched
