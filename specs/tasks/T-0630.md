# T-0630 [INS] Console: US finance pull from the institution's bank by ACH and see what is on hold
REQ: REQ-INS-009 (after T-0617) · Sprint: 12
Files: apps/console/app/deposits/page.tsx, apps/console/app/deposits/Deposits.tsx, apps/console/app/deposits/actions.ts, apps/console/src/deposits.ts, apps/console/src/deposits.test.ts, apps/console/src/api.ts, apps/console/src/i18n.ts, apps/console/app/layout.tsx, specs/tasks/T-0630.md
Test first: TST-INS-009 at the screen.

A US institution's finance staff open Deposits in the institution console. The screen shows:
- "on hold" (USD the bank still holds) and "yours to spend" (the institution's own account);
- the latest pulls, each with its state, its hold date while on hold, and why it failed;
- a form to pull an amount in dollars, with a step-up (the payouts flow's) and an Idempotency-Key minted per attempt.

`src/deposits.ts` is the model. The tests cover:
- an amount parses to cents, and anything else is refused before the API is called;
- a held pull shows its date; a returned one says it was returned;
- a retry after a network error keeps its key; a new amount gets a new key;
- 404 (another institution) and FEATURE_OFF read as plain sentences;
- an IL institution's console shows no Deposits entry.

Done when: listed tests pass; `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm trace` green; only listed files touched
Out of scope: linking the bank account (Plaid, with the ACH contract), ILS direct debit. Stop and ask on conflict with the spec.

## As built
- The page follows I09's split: `src/deposits.ts` holds every decision, `Deposits.tsx` renders the form and
  `actions.ts` is the server action. The API client gains `achPulls` and `createAchPull`.
- Keys: an attempt keeps its Idempotency-Key until its pull lands, whatever the refusal, because the API's same
  key is the same pull. A changed amount is a new attempt. A refusal that created nothing (a 422) is harmless to
  retry with the same key.
- The nav shows Deposits only for a US institution's finance staff (`showsDeposits`). The page sends anyone
  else home, and answers FEATURE_OFF and 404 with a sentence instead of an error page.
