# T-0531 [PAY] Members set the name others see when paying them: the first name and last initial, sealed
REQ: REQ-PAY-008 (before T-0530) · Sprint: 12

Test first: TST-PAY-008. Decided 2026-10-30 (Zvi, for T-0530's "Avi E."): the name comes from the member, not from KYC. Kesher stored no member name before this card.

- `identity.member_display_name` holds the first name and the last initial as two PII-sealed `bytea` columns, one row per member. It is class P1 in the spec's §6, beside the phone.
- `GET /me/display-name` and `PATCH /me/display-name` take `{ firstName, lastName? }` and answer `{ displayName, firstName, lastInitial? }`. The display name reads "Avi E.", or "Avi" without a last name. The rest of the last name is never stored or logged.
- A name is 1 to 40 letters in any script, with spaces, hyphens, apostrophes and Hebrew geresh or gershayim, starting with a letter. Digits, URLs and emoji are refused.
- `createApp` takes the process's PII cipher (`main.ts` and the demo's `dev.ts` pass theirs). Tests get an ephemeral one.
- The demo seed sets each persona's name ("Avi Example" → "Avi E.").

The tests cover:
- "Avi" and "Example" read back as "Avi E.", and the stored row holds neither plaintext;
- a Hebrew name with a gershayim is kept;
- a name with digits or a URL answers 422;
- a second PATCH replaces the first;
- one member never reads another's name;
- the seed's Avi reads "Avi E.".

Done when: listed tests pass; Spectral clean; `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm trace`, `pnpm db:lint` green; the migration applied on Postgres 16 through the desktop handoff; only listed files touched
Out of scope: the app screen (T-0532), resolving a recipient (T-0530), erasing names at closure (the PII retention for P1 applies, as for the phone). Stop and ask before widening what is stored.

As built:
- **Storage.** The two columns are sealed under their own names, `identity.member_display_name.first_name` and `.last_initial`, so a value copied into the other column will not open. There is no blind index, since nothing looks a member up by name. club_app may insert and update a row but not delete it; the P1 retention rule applies as it does to the phone.
- **What is kept from the input.** The first name is NFC-normalised, with runs of spaces collapsed. The initial is the last name's first letter, upper-cased in its own script ("כ״ץ" → "כ"). Nothing else of the last name reaches the database or a log.
- **`createApp({ pii })`.** `main.ts` and the demo's `dev.ts` pass the process cipher. Tests get one with random keys, so what a test seals never outlives it.
- **The demo seed** sets a persona's name only when none is set, so a rerun writes nothing. All ten personas read "<First> E.".
- **Spec.** The live spec carries REQ-PAY-008, and the name is added to §6's P1 class. T-0532 (the app screen) is carded, and T-0530 now runs after this card.
