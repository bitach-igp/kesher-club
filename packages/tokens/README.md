# @kesher/tokens

Design tokens for Kesher Club (spec Tab 2, "Jerusalem stone and night sky"), compiled by
Style Dictionary 5. Task T-0006.

**Change a token here and it changes everywhere.** `tokens.json` is the only place a colour,
size, radius, shadow, duration or type style is defined. Web, console, admin and mobile all read
the generated outputs; nobody hand-types `#1E5BD8` or `16px` in app code.

## Files

| Path | What it is |
| --- | --- |
| `tokens.json` | Source of truth, W3C DTCG format (`$type`, `$value`, `$description`). Colour tokens keep their light value in `$value` and their dark value in `$extensions["club.kesher.modes"].dark`. `color.money.in` / `.out` are aliases (`{color.status.success}`, `{color.text.primary}`) and the `*Subtle` fills are `{ color, on, alpha }` tints that the build computes; none of them are hand-copied. |
| `sd.config.mjs` | The Style Dictionary config and build script (preprocessor that expands modes, the `kesher/*` transforms, the four formats). |
| `src/theme.generated.ts` | Committed copy of the React Native theme so the package typechecks without a build. Regenerated by `build`; a test fails if it drifts. |
| `src/index.ts` | Package entry: `light`, `dark`, `theme`, `Theme`, plus the WCAG helpers in `src/contrast.ts`. |
| `dist/` | Build output (gitignored). |

## Build

```
pnpm --filter @kesher/tokens build      # node sd.config.mjs
pnpm --filter @kesher/tokens test       # vitest: contrast claims, scale rules, output checks
pnpm --filter @kesher/tokens typecheck
```

The build writes:

| Output | Consumed by | Shape |
| --- | --- | --- |
| `dist/css/tokens.css` | `apps/web`, `apps/console`, `apps/admin` (import once in the root stylesheet) | CSS custom properties. `:root` holds light plus every mode-independent token; `[data-theme="dark"]` is the manual override from Settings; `@media (prefers-color-scheme: dark)` applies to `:root:not([data-theme="light"])` so dark follows the system unless the user chose light. |
| `dist/tailwind/preset.js` | The same web apps, via `presets: [preset]` in `tailwind.config` | `colors` point at the CSS variables (so dark mode needs no `dark:` classes), `spacing`, `borderRadius`, `borderWidth`, `fontSize` with line height and weight, `fontFamily`, `boxShadow` (`elev-1..3`), `transitionDuration`, `transitionTimingFunction`. |
| `dist/native/theme.ts` (= `src/theme.generated.ts`) | `apps/mobile` through `import { theme } from '@kesher/tokens'` | Typed `light` and `dark` objects with the same `Theme` shape. Numbers are px (no units), durations are ms, shadows are React Native `shadow*` props plus Android `elevation`, money typography carries `fontVariant: ['tabular-nums']`. |
| `dist/json/tokens.flat.json` | Design tooling, docs, the Figma sync | Flat `"color.bg.canvas"` -> `{ $type, $description, $value: { light, dark } }` map, raw DTCG values for everything else. |

Package exports: `@kesher/tokens` (theme + helpers), `@kesher/tokens/css`, `@kesher/tokens/tailwind`,
`@kesher/tokens/json`, `@kesher/tokens/tokens.json`.

## Rules

- Edit `tokens.json`, run `build`, commit `src/theme.generated.ts` with it. Never edit generated files.
- Every text colour pair the spec lists with a contrast ratio is asserted in `src/contrast.test.ts`
  with a real WCAG 2.1 luminance function. Changing a colour that breaks a claim fails the test;
  update the spec table and the test together, never silently.
- Spacing stays on the 4 px base (`space.N = N * 4`), tested.
- Elevation is light-only by design; dark surfaces use the `bg.*` tone steps instead.
- Amounts always set tabular figures (`typography.moneyHero`, `moneyHeroSymbol`) and never rely
  on colour alone: `money.in` is paired with "+" and `money.out` with "-".

## Known spec discrepancy

`color.border.strong` is documented at 3.06:1 (non-text, 3:1). That holds for the light value on
`bg.surface`; the dark value `#5D677B` reaches 3.21:1 on `bg.canvas` but only 2.86:1 on
`bg.surface`. The spec value is kept and the test pins the measured number; raising the dark value
is a spec change.
