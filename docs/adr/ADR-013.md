# ADR-013: The admin console talks to the API, never to the database

Status: Accepted · Decided: 2026-10-17 (Zvi, on Claude's recommendation)

## Context
The admin console (apps/admin, Next.js) was built on an `AdminData` port with a seeded in-memory
binding (T-0901–T-0905). It needs real data: customers, cases, complaints, flags, bindings, audit.
Two ways to get it: `/admin/*` endpoints on the API, or the console reading Postgres directly.

## Options
1. **Admin endpoints on the API** (chosen). The console's server side calls `/admin/*` with a
   staff token; the API enforces roles, two-person approvals, the audit hash chain and flag state
   in one place.
2. **Direct database reads from the console.** Faster to start, but every rule that makes the back
   office safe (approvals, audit chain, RLS roles, insert-only ledger) would be re-implemented in
   a second codebase, and the app role's database credentials would live in a second container.

## Decision
- Every admin read and write goes through `/admin/*` operations in `contracts/openapi.yaml`,
  handled by `apps/api/src/admin/*` over the existing services (approvals, flags, audit, cases,
  memberships, accounts). The console never holds a database URL.
- **Staff identity**: the console's server side signs a short-lived (5 min) ES256 JWT with its own
  private key (`ADMIN_API_SIGNING_KEY`), `aud: kesher-api:admin`, `sub` = the Identity Center
  subject, `roles` from the ID token. The API verifies it against `ADMIN_STAFF_JWKS` and maps it
  to a `Principal` with role `admin` plus the staff roles; `/admin/*` operations require it and
  refuse member and agent tokens. No shared secret, no user token forwarded (REQ-AGT-004 spirit).
- The `AdminData` port stays; `httpAdminData` binds it to the SDK client. The in-memory binding
  remains for tests and `ADMIN_DATA=memory` in local/preview only; `ADMIN_DATA=api` everywhere
  else, and the console crashes on boot without one.
- Writes are audited by the API (actor = staff subject) with the hash chain, never by the console.

## Consequences
- The contract grows an `admin` tag; the SDK is regenerated; Schemathesis covers it.
- Cards: T-0906 (staff token, flags, bindings, audit), T-0907 (customers), T-0908 (complaints
  and alerts), T-0909 (monitoring rules that feed the alert queue).
- Admin operations are off the MCP surface: they carry no agent scope and the gateway never lists them.
