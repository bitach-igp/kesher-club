# ADR-005: Feature flag system

Status: Proposed · Decide by: Sprint 2

## Context
See the live spec, Tab 3 §4.

## Options
- OpenFeature + Postgres provider

## Recommendation (draft, 2026-10-18, for Zvi to accept or amend)
Keep the registry we have: `config/flags.json` as the only place a flag is declared (constitution
art. 8), the Postgres flag store with two-person flips through the admin API (T-0906, REQ-ADM-002),
and `FeatureFlags.isOn(key, context)` as the one interface app code calls. OpenFeature is worth
adopting only as that interface's shape, so a hosted provider can be swapped in later without touching
callers; it is not worth a dependency today, since the provider we would plug in is the Postgres store
we already wrote. Per-party targeting (the internal cohort, the pilot institution) is the next feature
the store needs, and it is a column, not a product.
