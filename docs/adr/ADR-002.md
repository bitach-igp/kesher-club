## Recommendation (draft, 2026-10-18, for Zvi to accept or amend)
Temporal Cloud, when the money flags turn on; the plain scheduler until then. The workflow bodies
(`runLoad`, `runSend`, `runPayout`, the allowance run) are already deterministic functions over an
activities interface with the idempotency key as the workflow id, which is exactly what Temporal
hosts. What Temporal adds is durable timers (the 24 h cooling-off, the 2 h hold, the ACH hold) and
retries that survive a deploy; the sweeps in `apps/worker` cover that today and go away when the
workers run under Temporal. Cloud over self-hosted: no cluster to run before there is a team to run it.
Decide the namespace layout with ADR-006, since the money namespace is what the paging alert watches.
