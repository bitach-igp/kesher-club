# ADR-004: Auth vendor for social/org SSO and MCP AS

Status: Accepted · Decided: 2026-10-17 (Zvi) · Decide by: Sprint 2

## Context
See the live spec, Tab 3 §4. Institutions sign their staff into the console with their own IdP
(SAML or OIDC) and must lose access within 15 minutes of deprovisioning (REQ-AUTH-008). Members
sign in with passkeys, with Sign in with Apple and Google as optional social logins (REQ-AUTH-004).
Agents reach the API through our own MCP resource server (REQ-AGT-001..009).

## Options
- WorkOS vs Clerk for institution SSO + SCIM.
- Social login: the vendor's hosted login vs direct OIDC against Apple and Google.
- MCP authorization server: vendor-hosted vs in-house, audience-bound tokens.

## Decision
WorkOS for institution SSO and deprovisioning:
- SSO through WorkOS SSO (one connection per institution, SAML or OIDC behind one authorize URL
  and one code exchange).
- Deprovisioning through WorkOS Directory Sync: the institution's IdP pushes SCIM to WorkOS; WorkOS
  pushes `dsync.user.*` webhooks to us, which the adapter maps to the port's SCIM events. A nightly
  `listDirectory` drift check compares the directory against the local staff table.
- The adapter is `WorkOsOrgIdPAdapter` in `packages/adapters/src/workos` behind `OrgIdPPort`;
  the simulator stays the default binding until an institution asks (flag `auth.orgSso`).

Social login stays on the direct Apple and Google adapters (T-0117): both are already built, carry
no per-user vendor cost, and keep Sign in with Apple parity (App Store 4.8) in our hands.

The MCP authorization server stays in-house (T-1001..T-1005): audience-bound tokens issued by our
auth service against our passkeys; a vendor AS would add a second identity for the same member.

## Consequences
- Per institution we store the WorkOS organization id, directory id and the inbound SCIM bearer
  as configuration, never in code; the WorkOS API key and webhook secret are secrets.
- `OrgIdPPort` is the only surface the console touches; swapping WorkOS for Clerk later is a new
  adapter passing the same contract suite.
- Deactivated subjects are refused at the next SSO callback even before the 15-minute window
  closes, because the adapter keeps its own deactivation record from the webhooks.
- WorkOS pricing scales per connection; the first institution's contract covers it.
